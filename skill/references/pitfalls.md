# 踩坑清单

按触发条件选择一项，先保留失败材料，再从第一个不满足的合同开始定位。E 编号对应[项目观察记录](../evidence/project_observations.json)，其中软件故障注入、静态发现和实板结果各有标记。

| 编号与触发条件 | 排查步骤 | 通过依据或停止条件 |
| --- | --- | --- |
| E01：同名 Z20 资料、器件或连接器与实物不符 | 核对实物载板与封装；读取匹配设计的器件、PS/DDR 和约束；比较 bit 与 HWH 目标 | 器件和封装不一致停止加载；新板重建，旧候选保留作参考 |
| E02：更新固件后仍报摘要错误 | 找全 bit/HWH、媒体、启动和音频等引用；保存原摘要；用已有配套事务预览、应用及严格回退 | 同一事务更新相关引用；回退恢复原字节；未知修改先核对 |
| E03：CPU 等待超时后程序退出，但硬件状态不明 | 保存状态、错误和地址；核对超时发生点；检查是否仍有 DMA/总线访问；按既有流程确认停止/复位 | 停止未确认时保留缓冲；不能凭异常退出释放或重用 |
| E04：类别相同却数值不同，或核内快而调用慢 | 固定输入/模型/量化摘要，逐项比较；分别计量输入准备、搬运、缓存、提交、等待与读回 | 全输出满足事先约定；速度比使用相同范围，保留较慢样本 |
| E05：断电后多个外设同时失联 | 先确认设备身份、网卡枚举、AP/managed、地址与路由，再确认服务握手；使用原恢复入口；重建输入会话 | 持续心跳、输入和就绪各有记录；短探测成功不足以确认长期链路 |
| E06：分析偶发花图、切页后闪回旧结论 | 核对完成槽、写入代数及复制前后状态；分析使用独立只读副本；在途结果绑定 session/epoch；繁忙时丢旧等待任务 | 覆盖变化则丢弃；未标定的几何结果保持其来源和单位；采集率与分析率分别记录 |
| E07：收到启用回执后很快掉线 | 同时记录 ACK、绘制和续租时间；用可控慢绘制复现；减少关键路径渲染并缓存可复用文本 | 在原租约内完成工作，仍能在停服后撤销；不直接扩大控制时限 |
| E08：工具报成功标记却以异常码退出 | 保存主/子进程退出码；用最小空脚本与实际模块分别复现；核对依赖与扫描器；重新跑完整构建 | 模块识别、综合、实现和 bitstream 各自有结果；非零退出不能只凭已生成文件当作正常完成 |

DMA 的 TLAST、TKEEP、宽度和长度排查见 [PYNQ 工作流](pynq-bringup.md)及[原始开源复现文章](https://discuss.pynq.io/t/debugging-common-dma-issues-part-3/7157)。本队 E03 来自故障注入回归，E06 同时包含源码约束与历史相机观察；不将它们一律写成发生过的硬件事故。

每轮记录“触发输入、实际状态、单一假设、最小改动、复查结果”。如果新证据指向另一个层次，重新定位，保留此前失败记录；未取得原因时直接登记现象与缺少的观察。
