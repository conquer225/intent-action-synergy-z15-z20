# 同输入黄金参考与耗时核对

适用于 RTL/HLS 算法、整数模型、滤波器和自定义数值 IP。前提是有一份独立参考及确定的数据合同。输入为相同输入字节、全部模型/参数、量化规则、原始输出和实际后端；输出为逐项数值差异及分开定义的时间记录。

## 固定数值合同

先记录输入维数、轴顺序、数据类型、单位和预处理版本。模型摘要应覆盖权重、偏置、归一化及运行所需参数，不能只取一个文件名。规定累加位宽、舍入、缩放、饱和、溢出行为及类别顺序；正数半入、四舍六入和向零截断会产生不同结果。

至少准备一个能手算的小向量和实际业务输入。定点边界包括负值、零、舍入中点、饱和边界和最大累加量。参考值来自数学算例或已确认的独立实现，不由待验代码重新生成一份当作黄金值。

先用 CPU 参考建立预期，再进行 C/RTL/HLS 仿真和实际硬件核对。分别保留层级，实际后端来自运行状态或驱动记录。只有类别相等时，仍要继续比较完整输出向量。

## 导出格式

每行一个 JSON 对象，允许按 `case_id` 换序：

```json
{"case_id":"case-001","source":"recorded:session-a","input_sha256":"输入字节的64位小写十六进制摘要","model_sha256":"完整模型工件的64位小写十六进制摘要","quantization_id":"本题量化合同版本","backend":"实际实现名称","values":[3,125,-3]}
```

这段用于说明字段；可直接运行的数据在 `examples/golden/`，来源标为 synthetic。`input_sha256` 对规范化后的输入字节计算，双方必须固定 dtype、shape 和字节序，再保存这些元数据；必要时将元数据与字节一并纳入摘要。`model_sha256` 对固定模型工件或明确的文件清单计算。哈希由导出端从实际输入计算，不能手填相同字符串来取得通过。

本工具比较非空、有限数值的一维输出；多维结果先用约定的轴顺序展平，并把原 shape 和布局写进 `quantization_id` 或工件合同。多个任务/帧使用不同 case_id。重复 ID、NaN、空文件及缺少身份字段均为输入错误。

```sh
python scripts/compare_golden.py reference.jsonl actual.jsonl --actual-backend MY_PL_BACKEND
```

脚本先比较 case 集合和输入、模型、量化、来源身份，再比较每个输出。默认精确数值相等；整数不先转 float，避免大整数丢失低位。`--actual-backend` 只检查记录中的名称，真实硬件是否执行由板端日志和工件摘要证实。

浮点运算有独立误差依据时才使用容差：

```sh
python scripts/compare_golden.py reference.jsonl actual.jsonl --atol 0.000001 --rtol 0.00001
```

判定式为 `abs(actual-reference) <= atol + rtol*abs(reference)`。容差与模型版本一起固定。整数核原本约定逐位相等时，出现差异要定位原因，保留失败值。

## 不一致时找第一个差异

按输入字节、预处理、权重/偏置摘要、展平顺序、第一处乘加、缩放和输出顺序追踪。先确认有符号 INT8 的读取和提升，检查行主序/列主序、位宽扩展及中间溢出；再看缓存同步、物理地址、寄存器布局和新旧模型混用。一次只修改一个有证据的环节。定位提示词见 [integer-debug.md](../prompts/integer-debug.md)。

整数结果完全相同说明对应输入上的实现一致。分类正确率还需要独立真实标签；同一录制会话的重叠窗口应放在同一划分，训练与测试分别保存。教师一致、登记图回忆、合成流程测试和真实独立测试分别报告。

## 耗时怎么比较

对同一模型和输入，在相同机器负载下分别记录下列范围，并写明冷启动、缓冲复用、预热次数、样本数及统计方式：

| 范围 | 必须包含的工作 |
| --- | --- |
| PS 预测调用 | 约定的量化/输入准备及软件预测 |
| PL 预测调用 | 与 PS 对齐的量化/输入准备、缓冲搬运、缓存同步、MMIO、硬件运算和结果读取 |
| 硬件提交至完成 | 从真正提交到驱动观察完成；轮询或调度开销按实际说明，不能直接当作纯计算周期 |
| 端到端 | 另行定义采集、窗口形成、网络、推理、渲染及输出是否计入 |

同范围速度比为 `T_PS / T_PL`。小模型可能因传输和 Python 调用更慢，本队 E04 就出现过 PS 约 2.066 ms、PL 预测调用约 13.177 ms，而提交至完成约 0.779 ms 的同一输入记录。不能用较窄的提交耗时替换完整调用耗时。[历史记录范围](../examples/z15-z20/README.md)

资源及时序由实际器件、完整实现和对应源码确定。隔离核综合估计与整机实现分别列出，缺少对应报告的字段保留未测。提示词见 [report-analysis.md](../prompts/report-analysis.md)。

## 验证效果与失效条件

本包离线测试能发现单项整数错误、输入/模型/量化/来源差异、丢样/重号、非有限数值和超出 float 精度的大整数差异。原工程 E04 的三个任务有历史真实 PL 整数一致记录；原始报告没有保存完整输入摘要和两份原始 INT32 向量，不能用本次新工具重新生成那次逐位核对证据。

参考算法本身错误、输入摘要由导出端误记、模型摘要覆盖不全或浮点误差合同未定义时，检查通过仍不足以验收算法。更换任务只需换输入、参考和模型合同；换板还要重新验证硬件和缓存接口。
