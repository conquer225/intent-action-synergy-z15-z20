# 板卡与会话恢复

适用于局域网内的两板或多设备系统：重启后服务失联、DHCP 地址变化、页面切换后旧结果出现、后台计算在重连后继续返回。前提是知道实际设备身份、原网络拓扑、服务入口和控制权限。输入为启动/网络/服务日志、当前配置与接收端时间记录；输出为故障所在层、最小恢复操作及恢复后的观察记录。

## 先找到断开的层

先核对设备身份和 boot/session 标识，再检查枚举、网络、服务和应用状态。可用的 Linux 只读入口包括 `lsusb`、`ip -br addr`、`ip route`、`iw dev`及原服务日志。SSH 能连接不表示应用端口可用；无线已关联也不表示到目标有正确路由。

登记每台设备当前接口、AP/managed 模式、地址、目标端口和路由。DHCP 地址与 COM 号从本次启动取得。目标身份由原服务握手或串口信息确认，不因某个地址以前属于某块板就继续使用它。公开日志去掉令牌、密码和私有配置。

按已有、可回退的流程修复当前这一层。已有脚本能完成临时入网时先复用它；在恢复演示过程中改开机网络策略需要单独验证。保存修改前后状态，不能用删除完整性校验来让配置更新通过。

网络恢复后依次检查原服务、持续接收、有效输入、标定及执行端就绪。使用原协议支持的只读状态/心跳方法，记录持续时间、数量、错误与断连。动作、停止和机械状态由实际执行流程观察；心跳通过不等于动作完成。

## 会话与结果生命周期

新连接建立独立会话，重连清空旧结果。当前模式版本只递增，结果必须匹配当前会话及模式，序号在该模式内严格递增。切模式后旧任务即使晚完成，也不能回填新页面。下一份输入仍在处理时，旧标签是否可以保留要由产品规则明确；失效必须可观察。

网络接收端用本机单调时间计算收到结果后的期限，避免直接相减两台设备未同步的时钟。源端还要限制采集/排队/计算造成的输入年龄；仅接收端 TTL 无法识别“刚收到但已经计算很久”的结果。心跳只说明连接活跃，不延长上一份分类的有效期。

控制权限与展示会话分别管理。恢复网络、恢复显示或收到新分类，均按原控制状态机处理使能与重新确认，不补发断连前积压的动作。准备好通信也要检查输入新鲜、标定和执行端就绪。

## 离线轨迹格式

工具检查实际日志，日志应由接收/显示程序的观察点生成。这里定义的是可移植审计格式；对接原应用时映射字段，保留原线协议。所有 `at_ms` 使用同一观察进程的本机单调时钟，单位毫秒，允许相同时间，不能倒退。跨进程或重启的日志需先明确时间关系，不能直接拼接。

| event | 必需字段 | 记录的事实 |
| --- | --- | --- |
| `connect` | at_ms、session、epoch | 接收端建立新会话；同一轨迹内 session 不重复 |
| `mode` | at_ms、session、epoch | 当前会话实际切换到更大版本，旧结果清空 |
| `result` | at_ms、accepted、valid | 原程序对一个结果的实际接收决定；accepted=true 时还需当前 session、epoch、递增 sequence，valid=true 时需 source |
| `display` | at_ms、valid | 实际显示状态；valid=true 时需 session、epoch、sequence、source，对应最近接受的有效结果 |
| `disconnect` | at_ms、session | 当前连接已断开 |
| `heartbeat` | at_ms、session | 原服务收到/观察到当前连接心跳，不刷新结果年龄 |

epoch、sequence 是非负整数，不能用布尔值。accepted 和 valid 是 JSON 布尔值。无效显示中的 class_id、scores 应为空或不出现；有效显示中的这两个业务字段可以另行记录，工具专门检查身份与生命周期，不判断其业务数值。

```json
{"event":"connect","at_ms":0,"session":"new-session","epoch":0}
{"event":"result","at_ms":10,"session":"new-session","epoch":0,"sequence":1,"accepted":true,"valid":true,"source":"recorded:sample-a"}
{"event":"display","at_ms":20,"session":"new-session","epoch":0,"sequence":1,"valid":true,"source":"recorded:sample-a"}
{"event":"disconnect","at_ms":30,"session":"new-session"}
{"event":"display","at_ms":31,"valid":false,"class_id":null,"scores":null}
```

运行：

```sh
python scripts/check_session_trace.py trace.jsonl --ttl-ms 2000
```

TTL 由本题任务周期确定，这里的 2000 ms 只是参数示例。脚本规定 `display.at_ms - result.at_ms >= ttl_ms` 时到期。现有程序若使用另一种边界约定，先统一审计合同。空日志或没有显示观察的日志返回输入错误；不能只记录正常分支取得覆盖结论。

`accepted` 及 `display` 字段必须来自被测程序实际行为。先根据规则填写“期望结果”再交给脚本，只能检查样例，不能验证该程序。用例应包括切页时在途结果、旧连接结果、新会话重复序号、断连、过期、无效输入，以及繁忙时的队列策略。

## 效果与失效条件

本队 E05 在断电后定位到 AP/managed 拓扑丢失，按原流程恢复后有 10.2 秒正常心跳；眼动定位和重新标定另行处理。E06 的回归覆盖旧模式在途结果及只保留最新待处理任务。E07 用慢绘制复现显示续租失败，再缩短绘制工作，保留原租约和停止规则。

本包新工具覆盖旧会话/模式、重号、到期、无效显示残留、时间倒退和布尔冒充序号。它依赖日志完整及观察点真实，不检查射频、BLE、电气连接、加密认证、实际屏幕外观或机械停止，也不自动恢复现场。相关数据缺失时，在[运行记录](../templates/run-record.example.json)列出未完成项；网络恢复、有效输入与动作验收分别记录。
