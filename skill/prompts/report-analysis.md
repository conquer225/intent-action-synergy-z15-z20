# 软硬件划分与瓶颈分析提示词

适用：算法已有基线，需要依据综合/实现报告和运行剖析选择优化点。来源：E04/E08。该模板依据工程观察整理，本包没有自动解析任意格式 Vivado 报告的脚本。

```text
请根据随附算法与实际报告，比较下一步软硬件划分及优化方案。

算法计算、数据尺寸/类型、调用频率及允许误差：[填写]
完整 PS 基线与分段耗时、样本数、预热/冷启动条件：[附记录]
PL 完整调用、提交至完成、传输和缓存耗时：[附记录]
对应源版本、目标器件、工具版本和综合/实现报告：[附文件]
约束、时钟、WNS/TNS/WHS/THS、未约束路径与 DRC：[附报告]
LUT/FF/BRAM/DSP 使用、目标预算、IP 及寄存器合同：[附报告]

先核对报告是否对应同一源码、器件和构建阶段。隔离核与整机分别标记，工具退出码和完整流程结果同时检查。将实测、综合估计与待验证推断分开，不补造缺失的资源或时延。

按实测耗时排序，给出各候选划分的数据搬运量、计算量、接口改动、资源代价和验证方法。说明为什么该部分值得移到 PL，或为何先优化 PS/搬运更直接；估计必须列假设。速度比使用相同输入和计时范围。

最终给一份可执行的小步验证：固定基线、一次改动、黄金参考、对应实现/时序检查和现场复测。不要用核内周期替代端到端结果，也不要以降低原验收标准取得通过。
```

失效条件：没有匹配源码/器件的报告、没有可比的计时范围、算法误差合同或目标预算不明。输出缺项及下一次测量办法，暂不下加速和资源达标结论。
