# Z15＋Z20 联动案例与方法来源

本案例说明通用流程从哪里来。原工程中 Z15 运行 PYNQ 及交互/控制页面，Z20 领航者承担共享整数 NPU 和相机计算；Z20 的实际接入包含 Linux FPGA Manager/UIO，不能把两端都视为同一个 PYNQ 安装。通用包采用板型、输入合同、资源所有权和会话生命周期这些可迁移部分。

| 观察 | 原工程事实、处理与结果 | 提炼到技能包 |
| --- | --- | --- |
| E01 板型身份 | 实物为 Navigator ATK-DF7010/7020P、XC7Z020 CLG400，早期 CLG484 候选与其不匹配。源码及拒绝测试要求先核对器件和封装，没有将错候选烧入实物的记录 | 构建清单、bit 和 HWH 目标逐层核对；换板重建匹配硬件 |
| E02 配套摘要 | 10/28 更新 Z15 固件后，音频页仍固定旧 bit/HWH 摘要，启动被拦截。通过原配套事务更新引用后启动正常，校验保留；随后新增的通用成对安装器只有离线验证 | 固件、元数据及引用一起更新，保持基线与严格回退 |
| E03 超时所有权 | 驱动的故障注入回归覆盖提交后超时/MMIO 丢失；进入不可继续提交状态并保留可能仍被硬件访问的内存，确认 reset 后才能释放 | CPU 退出与硬件停止分别取证。这项来源是软件回归，不登记成新增现场事故 |
| E04 全量输出与计时 | 10/28 历史实板记录中 20/180/40 维三个任务使用 `PL_z20_mlp`，记录整数参考一致。一个声音样本 PS 调用约 2.066 ms、PL 调用约 13.177 ms、提交至完成约 0.779 ms | 同输入、全输出、实际后端和相同计时范围分别核对 |
| E05 重启网络 | Z15 断电后恢复 AP 状态，缺少目标路由；复用原入网脚本恢复 managed 拓扑后，记录 10.2 秒心跳 connected=true、error=null。机构未使能；眼动重开与标定另行处理 | 先找到身份/网络/服务哪个层断开，再恢复并记录观察范围 |
| E06 快照与旧结果 | 环槽索引相同仍可能在复制中覆盖；快照比较写入代数并取得独立副本。异步分析只保留一个运行任务和一个最新等待任务；模式、断连和 TTL 清除旧结果 | 视频所有者不被旁路抢占；轨迹审计区分 session/epoch/sequence |
| E07 绘制与租约 | 45 ms/次绘制延迟的回归复现 ACK 后租约失效。缓存最多 256 个文字掩模并在未使能时准备，保留 300 ms 租约与停止规则；Z15 独立标签刷新约 154.98 ms，未打开机构接口 | 先量测阻塞段，减少界面工作，保持原控制时限；不把所有掉线归为网络 |
| E08 工具退出 | 源码扫描器依赖目录错误与空脚本退出异常分别定位。电脑重启后完整构建成功，历史 WNS 0.293 ns、WHS 0.034 ns，未放宽门禁 | 模块识别、工具正常退出、完整实现和板卡运行分别验收 |

E04 原始记录保存了后端、一致标记和缩放后的分数，没有完整输入摘要及两份原始 INT32 输出。因此本次比较器不能重验那次逐位一致；随包的正负 JSONL 是另行构造、可手算的离线样例。E08 的时序值只属于原 Z15 构建，不能填入新板/新题目的结果栏。

原始路径、类型和边界见[结构化观察](../../evidence/project_observations.json)。[脱敏 JSON 摘录](../../evidence/project_excerpt.json)保留历史结果的实际字段和来源摘要；[源码索引](../../evidence/source_index.json)可在原工程中核对。技能包的使用命令都从自身目录出发，这些历史目录无需复制到其他队伍的工程。
