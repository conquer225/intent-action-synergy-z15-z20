## 实际固定亮度结果

试验目录：`/home/xilinx/gl-latch-20261008-397040ef/`。
目标 30 秒，因为截止保护在 **0.334096 秒**提前退出，只有 **18 条**合格回执。
本轮是带计时的诊断样本，不能与此前无计时的 6.3/25.6 秒试验直接比较性能。
统计只覆盖非常短的样本，诊断额外调用也会扰动耗时。

- 20 次锁存调用中记录到 591 次 nanosleep，EINTR 为 0。
- 最长单次睡眠：请求 0.100 ms，实际 **14.173018 ms**。该锁存调用总长
  14.473334 ms，计数 28→29；没有在这次跳扫描或 DMA 报错。
- 锁存总耗时中位数 12.309 ms、最大 14.553 ms；等待整个刷新边界是正常成本，
  不能把这些总时长全部当作“不必要 CPU 计算”。
- 最后准备缓冲 1 的墙钟耗时 **21.521235 ms**；其中 paint 的复制计时为
20.549114 ms，刷新计时约 0.687 ms，逻辑计数 **45→46**。
  它在为后续扫描准备未来缓冲时跨过下一扫描，触发 `Corner copy missed next scan`。
- 最后准备区间无 nanosleep，记录一次非自愿上下文切换；线程 CPU 计数增量
  约 1.447 ms。这支持存在抢占/非运行等待，但不能拿墙钟减该 CPU 数值就精确
  声称“20 ms 全部被某进程抢走”。
- 另一准备区间耗时 12.656 ms，有两次非自愿上下文切换；准备阶段整体共记录
  20 次非自愿切换。上下文计数按调用线程采集，含义参见
  [getrusage 官方手册](https://www.man7.org/linux/man-pages/man2/getrusage.2.html)。
- DMA 状态 `0x11000`，错误/停止掩码未置位；三缓冲像素哈希相同。
  这是固定亮度模拟相位工作负载，不是实际四角 SSVEP 刺激合格。

内核为 HZ100，未开启 VIRT_CPU_ACCOUNTING_GEN/IRQ_TIME_ACCOUNTING/SCHEDSTATS。
因此微短区间 CPU 用量精度有限，`/proc/*/schedstat` 和运行队列延迟不可用，
报告明确写 null，不以 0 冒充“没有排队”。没有安装 perf、trace-cmd 或 cyclictest。

试验后另做 3 秒只读线程 CPU 粗采样：正式采集主线程约 38%、一个 Python 子进程
约 30%，另有多个 Python 线程/进程占用。百分比以单核 100% 为单位，属于事后窗口，
不是失败时刻的轨迹；不能证明其中任何一个就是抢占者，也不能据此宣布两核全满。
