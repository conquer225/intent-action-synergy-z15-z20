## 确认的运行目录保存缺口

正式 guardianloop-cyton.service 配置 RuntimeDirectory=guardianloop，
RuntimeDirectoryPreserve=no。systemd 停止服务可移除 /run/guardianloop，
同目录的校准存档和 wear-session 会一起失去。这能解释服务停止后无法
恢复的一个风险，不能据此宣称以前每次校准变化都由该配置造成。

60-primary-worker.conf 将设置 GL_PRIMARY_EXECUTION=async 和
RuntimeDirectoryPreserve=yes；在停止旧服务之前先加载保存目录配置。
/run 仍为本次开机的临时目录，不跨板卡重启沿用旧基线。新佩戴、模型、
通道、量纲与滤波契约校验保留；断流只撤销旧结果，不能伪造连续有效输入。
开始审计时板端没有 calibration-session.json，校准为 0，Cyton 无完整包。
不能凭部署恢复一份本来不存在的完成校准。

## 实时入口和部署保护

guardianloop_acquisition.py 默认同步，仅 unit 环境明确 async 时加入
--live-primary-worker；拒绝从入口命令行加入实时或隔离主窗口测试开关。
实时后台路径要求固定八通道、锁定接收器 by-id、ARM、连续采集、正式
状态路径和模型路径，无 ESP32 输出，不允许混用隔离回放开关。

主计算队列容量仍为 32 批，保持顺序、数组所有权、epoch 和 500 ms
时效检查。USB 主读队列的十包 IPC 会在每次 USB read 结束立即刷新
不足十包的批次，不额外等待凑够十包。显示遥测缓存只复用实际相同的
波形行，不改变模型输入或结果。SEED 沿用已部署的异步与按页面调度。

安装器复用 install_calibration_repair.py，新增严格的 primary_worker_update
分支：只允许六个源码、发布清单、服务覆盖、启动验证元数据和两份 HDMI
校验清单；拒绝网页服务重启、UI 源码和显示/开机程序更新。原网页和显示
PID 与启动 tick 必须不变。备份含旧正式发布全部文件、变化目标及已有
校准/佩戴文件；150 秒独立回退计时器保护安装，核验后才提交。

只重新校验文件与 ARM 模型，不调用 guardianloop_startup.run 或
load_production_pl。HDMI 状态仅更新 formal_hashes，boot-pins 仅更新
变更源码/发布清单和新增覆盖的指纹，防止下次启动因旧指纹拒绝新程序。

安装已保存旧 53 文件、11 个变化目标和 9 个 service/drop-in 原文件，
在停止旧采集前应用 RuntimeDirectoryPreserve=yes。停止采集后，
play-df4fc516.service 立刻以 status=1 退出。显示自身状态记录明确报错：
`Runtime admission revoked: Brain acquisition must already be running`。

此前仅核查显示 PID 与源文件指纹，没有检查其持续运行保护是否接受短暂
采集停机，这是本次接入遗漏。media_player 的 RuntimeWatch 持续调用
显示准入检查；它将采集的临时停止视为显示准入撤销。显示 finally 路径

original_restored=true / buffers_released=true。本轮没有主动调用 PL 加载，
但采集停机确实间接触发了显示退出和程序自身的 PL 恢复，不能声称 HDMI
未受影响。

安装器发现原显示 PID 不再运行，自动回退全部变化目标，没有提交新版本。

旧文件与候选 payload 的恢复包已生成；安装目录的校验备份保留。
