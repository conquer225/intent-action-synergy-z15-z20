- 复制加缓存刷新：中位数 2.509 ms，p95 3.517 ms，最大 14.193 ms。
  最后一次恰为最大值，返回后已跨过下一扫描，故不再提交该缓冲。
- 请求停车到当前缓冲索引确认：中位数 13.493 ms，p95 14.429 ms，最大 21.327 ms。
  这是等待扫描边界的函数耗时，不可简单和复制最大值相加当作正常每帧成本。
- VDMA 状态 `0x11000`，已有停止/错误掩码未发现 DMA 故障。
- `pixels_constant=true`、`display_halted=true`、`buffers_released=true`、
  `original_restored=true`；正式采集 PID 23531、网页 PID 26555、NRestarts 均为 0。

## 已确认、推断和仍未知

已确认：平均工作量不大，但现有“收到当前扫描回执后才复制下一帧”的策略偶发
错过更新截止时间。单次 CPU 函数耗时低于 16.5 ms，也不能证明剩余扫描时间足够。
不把缺失的更新重新计为准时帧，不复用旧证据维持方向。

推断：迟到的回执以及复制/缓存刷新调用的长尾可能叠加，压缩下一次更新的余量。
当前记录是合并函数的墙钟耗时，尚不能区分 NumPy 复制、缓存刷新与 Linux 调度
各自贡献；也没有证据把问题归到无线吞吐、识别模型或 FPGA DMA 硬件故障。

未知：完整统一页面和真实脑电负载下的时序；真实光学频率、撕裂、四频识别及
休息拒绝性能。本次固定亮度不能作为这些项目的通过证据。
