## 完整记录负载结果

最终第 6 组不启用阶段计时探针，按 250 Hz 回放已有 156 秒记录，共 39,000 包。
页面策略固定视频页，不自动发起运动想象试次；ARM 情绪／疲劳按正式路径计算，
SEED 和 SSVEP 候选按页暂停。同时既有 HDMI 会话播放静音 20 fps 缓存视频。
正式采集服务没有停用，因此这是附加隔离回放与现有显示的并行压力检查，
并非直接运行正式串口采集的个人识别测试。

- 消费 39,000/39,000 包，生产者约 156.001 秒完成；最长生产迟到约 17.1 ms，
  没有超过 100 ms 的生产批次迟到。
- 情绪出现 3 个 `prediction` 输出，疲劳出现 3 个 `NORMAL` 输出；
  同时还有质量拒绝／校准／积压失效状态，不代表全部时段可用。
- 输入年龄 p95 292.992 ms，最大 1,121.491 ms。
- 单包主处理时间最大 714.611 ms；主进程 CPU 69.630 秒，子进程累计 CPU 99.306 秒。
- 最后监测快照显示 5 次流状态恢复、380 个陈旧包弃用，
  原始输出中有 4 次 `PROCESSING_BACKLOG` 撤销。
  其中校准完成后的积压撤销仍保留 15/15 校准及 `calibration_retained=true`。
- 回放退出正常，无监测错误、无剩余子进程。正常退出不等于实时性通过。

第 4／5 组开启的探针不同，会引入额外开销，只用于定位；不能直接用其总 CPU 或最大值
声称新版本的整机性能提升。前一次不带探针的视频页回放输入年龄 p95 297.294 ms、
最大 668.206 ms；本轮 p95 相近、最坏值更高，不能宣称调度长尾已经解决。
时序差异导致两次接受窗口数不同，不按窗口序号强行比较模型结果。

## 显示观测及剩余问题

220 秒只读观测包含回放启动／收尾，共 203 个视频状态快照、202 个可比较区间。
软件帧进展比值加权平均约 15.86 fps，最低约 3.95 fps，86 个区间低于 16 fps。
这些是约一秒状态快照间的计数差，不是光学或逐扫描帧率测量；
不能据此宣称物理屏幕稳定达到 16 fps。

阶段定位还确认显示遥测工作进程有序列化开销：第 5 组 291 次发布累计约 14.36 秒
CPU，最长墙钟约 620 ms。它在独立进程，不等于同步阻塞主循环；
可视为进一步排查资源竞争的候选，不是已证明的唯一根因。
主循环日志写入在该组最长约 19.5 ms，没有证据把全部长尾归因于 SD 日志写入。

推断：显示、主监测和后台计算的资源竞争尚未消除。未知：各次长尾中调度、
同步等待和 I/O 的具体占比，以及显示内存调试读数异常的原因。
下一步应限定显示／遥测的重复工作与预算，先做隔离对照；
不放宽新鲜度，不删除坏信号门控，也不要求用户重新佩戴来调软件。

随后已完成遥测缓存和第 7／8 组完整记录对照，详见
[遥测与 HDMI 资源竞争](TELEMETRY_RESOURCE_RELIEF_20261009.md)。波形发布 CPU 中位数
约 64 → 23 ms，39 项板端回归通过；仍有 831 ms 输入积压与视频低谷，尚未替换正式版。

后续第 9～13 组完成 MI 待机快照减负与 CPU 角色分配对照，详见
[MI 待机减负与调度对照](MI_IDLE_RESOURCE_RELIEF_20261009.md)。单次角色分核回放
输入年龄最大 453 ms、无处理积压撤销，正常预测路径已覆盖；视频仍有低帧率区间。
隔离候选保留，正式文件和常开入口未替换，下一步集中显示提交／备帧路径。
