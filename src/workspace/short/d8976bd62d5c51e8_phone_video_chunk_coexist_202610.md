## 边界与恢复

本轮用户要求长视频分块缓存、手机播放入口及脑电/眼动共存测试，并明确不能发出声音。全过程静音：不打开音频输出设备，不播放扬声器声音，不操作实体执行器。原始上传视频保留。

目标板为 Z15 / xc7z015clg485-2。仅临时加载现有 `/home/xilinx/tobii_z15/overlay/eye_wifi.bit`，SHA256 为 `8b52892466a1b4d025c5c693a951727ae6215e57ca3e5fa0dedaa2a1d510d50f`，配套 HWH 为同名文件。测试后停止显示 DMA、释放帧缓冲，恢复 `/home/xilinx/jupyter_notebooks/guardianloop_pynq/guardianloop_pynq.bit`。每次播放有独立恢复定时器，不修改开机配置，不生成新比特流。

正式采集及网页不停止。当前正式脑电任务使用 ARM，因此本轮显示 PL 可以与其共存；不意味着滤波共存候选或任意其他 PL 都能同时加载。

## 实现

源代码在 `phone_video_upload/`：

- `chunk_cache.py`：独立块、逐帧 CRC、LZ4 解压、两个固定 RAM 槽、生产者/消费者所有权、损坏拒绝及取消。
- `prepare_chunks.py`：离线准备副本，核对软件 BGR 参考，不修改原始文件；成功才原子发布缓存清单。
- `media_server.py` / `player.html`：手机上传、校验、显式准备、播放、暂停、继续、停止。访问码通过 URL 片段及请求头传入，不写入请求日志；拒绝跨来源及任意路径/命令。
- `media_player.py`：定时送屏、VDMA 帧选择与扫描进度检查，不把 60 Hz 扫描次数算成新视频帧数。结束或故障后回退原 PL。
- `playback_recovery.py`：仅处理本次拥有的 PID。已正常结束的旧会话定时器不会重配新会话的 PL；已在第二次播放期间验证旧定时器退出、不停止新进程。
- `audio_probe.c`：只解码到内存并核对时间戳，没有 ALSA/扬声器输出。

候选每次播放最多 180 秒，原文件上传最多 512 MiB，缓存每段最多 4 GiB，准备输入最多 600 秒，准备过程中保留至少 1 GiB 磁盘余量。当前没有永久开机安装或“三小时自动换十个视频”的调度功能。解码准备可能慢于视频时长；不能描述为实时手机镜像。

## 控制及恢复补充

`player_controls.json` / `play-d710b94b-report.json`：真实隔离 HDMI 播放器通过同一手机入口 API 完成暂停（帧号稳定）、继续（帧号前进）、停止并恢复原 PL。测试客户端是电脑，不冒充真实手机交互验收，也不用于宣称帧率通过。

当前手机候选入口已注明多任务 16 帧未通过；压力按钮明确标记“360p 细节诊断”。默认诊断不再自动选择未通过的差分/全 BGR 缓存。用户原文件、已有缓存和失败诊断全部保留，不是永久正式升级。

本地 30 项视频 Python 测试、Z15 30 项同类测试以及页面 JS 检查通过。板端第一次测试收集曾误导入电脑专用启动脚本，已更名为 `launch_after_prediction.py` 后重新运行；这不是设备采集故障。统一交互原型另有 18 项 Python 测试和页面脚本检查，但尚未接到实际 HDMI/眼控/轮椅输出。

`final_audit.json` 核对正式版 48 个清单文件、保护文件、采集/网页服务 PID 与重启次数不变，原 GuardianLoop PL 恢复。本轮所有音频输出及实体控制均关闭，眼动 USB 诊断有效样本均为 0，故不能宣称真实眼控已通过。真正音轨外放、音画同步、长期任意视频、现场脑电识别和实体轮椅运动均仍是未验收项。
