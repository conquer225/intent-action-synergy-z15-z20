# 候选 DMA 缓冲区所有权合同（未满足，禁止正式接入）

适用于 `primary_filter_dma.py` 的 80×64-bit MM2S/S2MM 成对缓冲区。本文是准入条件，不描述已部署功能。

## 状态与处理

| 状态 | 触发 | CPU 可读 RX？ | 可复用/释放 TX、RX？ | 可重新启动 DMA？ |
|---|---|---:|---:|---:|
| 空闲 | 尚未设置任一 DMA 长度寄存器 | 否 | 是 | 可在确认配置后启动 |
| 在途 | 已设置 RX 长度，至两通道完成确认 | 否 | 否 | 否 |
| 完成 | MM2S/S2MM 均 IOC+Idle、无错误、RX 长度正确，且输出检查通过 | 是，先 invalidate | 是 | 是 |
| 所有权不明 | 任何超时、AXI 错误、PL 复位或进程异常 | 否 | 否 | 否 |

现有驱动可在**进程仍存活**时执行前述拒绝与 `_quarantined` 引用保留；11+3 个寄存器模型测试只验证这个范围。这个 Python 字典不跨进程存活，也不是物理内存保留机制。新的 Python 进程无法凭 DMA 的 `Halted`/`Idle`、IOC 清零或 GPIO 状态证明此前 HP0 的未完成读写已结束。

2026-09-28 补强：初始化/关闭阶段的 DMA reset 或 halt 超时也已锁存进程内故障，禁止重复 `reset()`/`close()`；常规测试现为 13 个，在途复位测试仍为 3 个。这只封住一个软件重试漏洞；本文四项跨进程准入保证仍未满足。

2026-09-28 再补强：`PrimaryFilterDMA` 构造默认在任何 MMIO/分配之前拒绝物理调用；`test_only=True` 仅供隔离的寄存器模型测试。14 项常规测试及 3 项在途模型测试通过。这是**禁止危险入口**，不是已解决跨进程物理页持有。板上只读检查确认运行 `5.4.0-xilinx-v2020.2`、存在内核构建目录及 `/dev/xlnk`，但没有 `/dev/udmabuf*`、`/dev/dma_heap/*` 或设备树 `reserved-memory` 节点；需单独实现并批准内核持有方案。

进一步核对板上 PYNQ 源码确认，当前 `allocate()` 用的是 XRT/ZOCL 路径，不能把 `/dev/xlnk` 当作缓冲区持有证明；`PynqBuffer.close()` 是空操作，已将候选正常/失败释放改为 `freebuffer()`。工作进程死亡时 XRT BO 是否仍由内核长期保留，尚无证明，按不保留处理。

用户授权后已建立隔离的第一方内核持有候选：`kernel_owner/`，离线 ARMv7/匹配内核编译及共享状态机测试通过。它将页保持在模块中，首次 RUN 后不允许正常卸载，工作进程终止后锁为 `UNKNOWN`；**尚未加载/杀进程实测，且本板支持强制卸载，所以不能将本合同改为已验收。** 详见 `../output/kernel_owner_offline_20260928/RESULTS.md`。

## 必须补的四个保证

1. 系统内至多一个设备所有者，其他服务只能通过受控请求队列提交批次，不能直接访问 DMA/GPIO MMIO 或加载覆盖该链路的 Overlay。仅写在注释里的“单调用者”无效。
2. 进程崩溃、被 SIGKILL、服务重启时，**可能在途的物理页不能回到通用 CMA 分配器**，直至获得可信的硬件排空证明或经过已验证的 PS/HP 级恢复。可考虑由不随工作进程退出的内核/保留内存设施持有 DMA 区；普通进程全局变量、日志文件或 `atexit` 均不够。
3. 异常复位后需可观测的读/写未完成事务排空条件，或另有板级实验支持的整 PS/HP 恢复规程。当前测试台 `reads_pending/writes_pending` 只在仿真可见；候选 GPIO 不导出这些计数。不能将 `DMA reset done` 等同于 HP0 已排空。
4. 开机与服务重启路径读取 boot/session 故障锁存状态。若上一会话存在所有权不明，默认拒绝新分配/新 DMA，并明确记录需要的受控恢复。故障帧不发布，不参与 EEG 模型或 SQI 基线。

## 验收用例（待实现，非通过项）

- 两个进程同时打开：第二个必须被拒绝，且不触及 MMIO。
- 在 S2MM 部分写入后杀死工作进程：持有者仍保留原物理页，其他 CMA 申请不得获得这两个地址；新工作进程不得自动重启 DMA。
- MM2S 与 S2MM 同时在途时分别触发 PL 复位、DMA reset、AXI 背压/错误：记录硬件可见的 AR/R/AW/W/B 完成与 HP0 排空，再检验恢复决策。
- 正常完成且缓存失效后，80 字输出与 ARM 黄金结果一致；在帧边界哨兵外无写入。长时间和重复试验均满足后才能放开释放。
