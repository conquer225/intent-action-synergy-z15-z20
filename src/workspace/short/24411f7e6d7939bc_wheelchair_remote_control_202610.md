# 手机持续遥控更新（2026-10-15）

**后续现场报告：四个按钮未对应四种实体动作，方向验收失败。** 下文通过结果只证明断动力时的指令、租约和停止状态，不证明轮椅实际方向正确。后续 GPIO 初始化对齐和引脚检查见 [错向排查记录](WHEELCHAIR_GPIO_READBACK_20261015.md)。

用户明确接受：点击方向后持续执行、不需长按、不设固定正常行驶时长；停止、失联、页面退出时撤销驱动，重连不自行恢复。修改前用户报告电机动力已断开。原“一次短动作”与未完成的 60 秒方案不作为本次目标。

## 控制链与边界

- 手机页 `system_mobile.js`：每 200 ms 心跳；隐藏/退出页面、请求失败或强制停止时清除本地持续指令，尽力提交 STOP。心跳只维持同一个已点击的命令，不能创建方向。页面操作采用当前服务令牌；STOP 旋转令牌，旧请求不能跨过 STOP 启动。
- Z15 `media_server.py`：独立遥控锁，避免被 HDMI/视频查询占住；只接受与当前命令匹配且间隔不超过 750 ms 的心跳。过期心跳拒绝，不刷新旧指令。服务重启换页面令牌。
- Z15 `wheelchair_link.py`：每次新方向先提交 STOP，间隔至少 350 ms，并等待首个前台心跳确认；随后显式开启手动租约、持续发送同一方向的新 ticket。旧启动文件不重放；失败清除意图，不自动重新许可。
- ESP32 `motion_guard.c`：手动租约为接收端签发时间起 500 ms，持续续期不受原 1 秒台架上限影响。未使用的许可也到期。STOP/失联/故障撤销；新启动身份隔离旧会话，重复命令不能续命。SSVEP 和本机串口 ARM 仍用原 300 ms ticket 与 1 秒台架上限，未静默取消脑控门控。
- GPIO10/11/12/13 与原接线映射不变，同方向续期不反复切继电器，换方向先全低。仅更新 ESP32 应用分区，不写引导器、分区表、NVS、Z15 PL、模型或校准。

手机心跳丢失和 ESP32 本地租约是两级撤销机制，不能把软件租约数字视作车轮实际刹停时间或距离。网页停止不是独立物理急停，GPIO 写成功也不是车轮反馈；尚未完成载人驾驶验收。
