# Tobii IS4 接 Z15：实板调试入口

2026-10-05：用户已确认上一轮三点方向标定后的选区、高亮、停留确认和防重复触发正常。新增离线句子发声、音乐和无声视频模式，使用方式见 [LOCAL_MEDIA.md](LOCAL_MEDIA.md)。完整素材在电脑端准备，板端声音设备和真人菜单操作仍需验收。下面保留先前探针与标定调试流程。

更新：2026-10-04。独立 ARM Linux 探针已取得实际 640×480 灰度图像和约
60 Hz 眼动数据包；有效注视、个人校准和稳定左右中识别尚未通过。
运行时不需要电脑 ROI 回传或 x86 厂家库。

当前板端目录 `/home/xilinx/tobii_z15`。源文件由固定版本的 Apache-2.0 参考
生成，来源见 [THIRD_PARTY.md](THIRD_PARTY.md)，实测见
[verification.md](report/verification.md)。

```powershell
python ps_tobii/tools/make_is4_probe.py
python -m unittest discover -s ps_tobii/tests -v
```

板端编译与采集：

```sh
cd /home/xilinx/tobii_z15
gcc -std=c11 -D_POSIX_C_SOURCE=200809L -O2 -Wall -Wextra \
  src/is4-probe.c -o is4-probe $(pkg-config --cflags --libs libusb-1.0 openssl)
sudo sh run_board.sh --seconds 30
```

默认采集 120 秒，Ctrl+C 停止。CSV、事件记录与两张轮换 PGM 在
`/dev/shm/tobii_z15/current`，每秒保存一张图；实际图像流仍约 30 Hz。
RAM 数据在重启后丢失，再次运行会覆盖同名文件。采集结束后再保存到 SD：

```sh
mkdir -p captures/saved_run
cp /dev/shm/tobii_z15/current/gaze.csv captures/saved_run/
cp /dev/shm/tobii_z15/current/frames/events.csv captures/saved_run/
cp /dev/shm/tobii_z15/current/frames/*.pgm captures/saved_run/
```

每次只运行一个探针。真实图像来自 TTP `0501`，普通 OpenCV 暂不能打开
设备的自定义 UVC 格式。`--inspect` 仅查询设备元数据、原有校准备份和字段
说明；未清除、计算或改写校准，未改写显示几何。

实际 IS4 字段 `0x1b` 为合并有效性、`0x1c` 为合并坐标、`0x16/0x15`
分别为左／右眼检测。缺少有效标志、未检测到眼睛或离屏候选不能触发动作。
诊断探针只记录数据。HDMI 已接入实验性九点校准 worker，校准采样、
失败恢复和真人测试结果见 verification.md；停留控制尚未交付。

## HDMI 计时提示

`src/hdmi_guide.py` 默认显示准备页。准备倒计时 5 秒，九个白点依次显示，
每点移视 1 秒、提示采集 3 秒；没有采样回应时继续提示等待，单点总计
10 秒停止。处理结果最多 45 秒。真实模式处理时继续看中央白点，
正常眨眼即可，结束页明确提示可以移开视线。

默认模式为显示演练；启用 `--live` 后 `start`/PS_KEY0 接入真实校准。
`--preview` 只演练画面，页上始终标明“不采样”，不能当作完成个人校准。
实际成功状态还需要校准器返回结果和真实有效注视样本，不能由倒计时生成。

板端已有配对 r9 overlay、显示库和中文字体时：

```sh
cd /home/xilinx/tobii_z15
sudo sh display_session.sh guide --seconds 900
# 演练九点提示，不连接眼动采样、不写校准：
sudo sh display_session.sh guide --seconds 90 --preview
```

两种模式均只允许一个 HDMI 进程。停止或到时先停 DMA、释放 CMA，恢复
进入前的 overlay；临时停止的 EEG 服务若原为 active/activating，恢复后再启动。
不改变服务的开机启用状态。默认准备页 15 分钟后退出，本次未安装开机服务。
渲染样例在 [report/guide](report/guide)，运行控制文件位于
`/dev/shm/tobii_z15/guide`；此接口仅供本地调试，不是用户屏幕上的操作要求。

### 板载按键

程序默认读取现有 Linux `gpio-keys`：`PS_KEY0`（MIO12，Linux code103）
开始九点画面演练，`PS_KEY1`（MIO11，code108）暂停。结束或暂停后可再次
按 PS_KEY0；运行中重复按开始键不会重置倒计时。屏幕底部同时显示操作。
默认按键启动演练，不发送 USB 校准采样命令；`--live` 接入实际模组。

请按板上丝印为 `PS_KEY0` 的按钮。`PS_RESET`／`RESET` 会复位整块板子，
使当前 HDMI 程序退出、屏幕熄灭；当前尚无开机自启，复位后需重新启动显示程序。

按键通过 `/dev/input/event*` 的 `keys` 设备读取，不重新配置 MIO，也不
导出已由内核占用的 GPIO。50 ms 防抖、忽略自动连发、启动时已按住的键需
先松开；输入事件丢失时停止程序，不猜测开始动作。`--no-buttons` 可禁用读取。

`tools/analyze_capture.py CSV --seconds 时长` 统计时间戳与帧号缺样本；USB
错误计数为零仍可能缺帧。私人图像、完整 CSV 和备份在忽略的 `local/`
或板端目录，公开报告仅保存统计与无脸协议样本。

### 真实校准试测

先生成诊断适配源，将 `build/is4-probe.c`、`src/calibration.c` 与 `src/calibration_policy.h` 部署到
板端 `src`，板上编译：

```sh
gcc -std=c11 -D_POSIX_C_SOURCE=200809L -O2 -Wall -Wextra -Werror \
  src/calibration.c -o is4-calibration $(pkg-config --cflags --libs libusb-1.0 openssl) -lm
sudo sh display_session.sh guide --seconds 900 --live --width-mm 220 --height-mm 160
```

模组固定屏幕下沿中央，PS_KEY0 开始、PS_KEY1 中止。每轮保存原校准、
原屏幕几何、实际 gaze.csv 与命令状态到权限 0700 的 `captures/cal_*`。
单独读取头偏移 16 的固件错误码，按序号和操作匹配回应；偏移 8 在本机为 1，
不是错误。无参数校准命令使用空负载，不沿用旧探针的两字节前缀。

本机 `05a0` 几何写入返回 `20000501`（不支持），读回核实原值未变后
允许继续试测；命令行宽高是拟设置值，没有写入成功，不能认定屏幕几何已匹配。
坐标精度尚未验证。失败或中止重新上传原校准，读回逐字节核对。
完成至少九个点后才计算应用，再取得 10 秒注视流；新校准数据有变化且
至少 30 个有效候选才显示完成，处理进程退出成功也是必要条件。
这一门槛不代替准确率和长期稳定性验证。


### 宽松试测

用户要求放宽校准流程后，新增显式 `--relaxed`：

```sh
sudo sh display_session.sh guide --seconds 900 --live --relaxed --width-mm 220 --height-mm 160
```

换点后先稳定 2 秒；首次采集顺利时每点约 5 秒。固件明确返回
`20000502` 时，保持同一白点，间隔 2 秒重采，单点最多 3 次、35 秒。
原生会话总限时从 180 秒延至 420 秒。USB 超时、断连、参数或状态错误
不自动重发，避免在前一命令完成情况不明时重复写入。全部失败仍退出并
恢复原校准，屏幕显示恢复核对结果。未启用此开关的原流程保留。

这些设置放宽板端等待和重试，没有改变 OEM 固件内部的瞳孔质量、距离
或头位门槛；现有程序本来没有另设距离/头位拒绝条件。九点接受、计算应用
成功、模型有变化及真实有效样本的确认仍保留，不能把负错误码转换成成功。


实际采样时屏幕下方增加只读状态：最近约半秒的左右眼检出比例、有效
正值瞳孔直径比例，以及检测到的眼原点 Z 平均距离。检测到眼睛不等于
取得瞳孔参数，两项分别显示。没有定位不显示 0 cm，超过 1.5 秒未收到
更新显示等待新数据。提示不增加采样门槛、不改变固件状态和校准成功判定。


本地诊断 worker `--inspect-options` 只查询设备能力与照明模式，不进入
个人校准。`--check-tracking` 做 3×5 秒的模式对照，保存原模型并在结束后
核对一致；不清除、不采校准点、不计算应用。GUI 本地 `check` 调试动作
显示固定中央白点；PS_KEY0 的普通操作仍启动九点真实校准。


真实九点后 IS4 校准读回可达数百 KB，不能沿用诊断请求的 4 KB 上限。
worker 备份/上传容量按既有约 2 MiB TTP 帧上限受限，动态分配发送缓冲，
模型仍核对 blob TLV 类型及内外长度。原始读回先保存到 private capture
目录，收到文件不等于模型校验/应用完成，以最终结果和退出状态为准。

### 独立方向验证与模型恢复

2026-10-04 已有一次九点全部被接受、287034 字节新模型及随后
10 秒 603/603 有效样本的实板记录。重启后模组读回原 1188 字节模型，
板上私人目录保留个人模型。以上仍不是方向准确率或持续运行验收。

`is4-calibration CAPTURE 220 160 --inspect-model` 只读当前模型；
`--restore-model /绝对路径/模型.bin` 上传后严格逐字节核对，差异触发
测试前模型恢复。大模型按 8192 字节 USB 传输上限拆分，每段有独立
8 字节通道/长度封装；上传期间接收流继续排空，图像在恢复后才订阅。
整帧直接上传以及只排空少量图像的实现均实测失败，不能沿用。

当前原个人模型上传命令已收到固件成功回应，读回长度相同但内容不同；
其原因尚未确认。严格恢复没有通过，测试前模型已恢复并读回一致。
`--validation-model /绝对路径/模型.bin` 可显式检查这个已被固件接受的
候选，不把“上传成功、大小相同”当作模型恢复已验证。

```sh
sudo sh display_session.sh guide --seconds 1800 --live \
  --width-mm 220 --height-mm 160 --validation-model /绝对路径/模型.bin
```

该页 PS_KEY0 开始方向验证，PS_KEY1 中止。5 秒准备后，左、中、右
各出现 3 次，每次稳定 2 秒、统计 8 秒；不执行校准点采集或计算应用。
目标先真实显示，再发送采样标记。三区域边界固定为屏幕横向 1/3 和 2/3，
没有使用本轮数据拟合判别阈值。逐段要求至少 300 个样本、有效率及
有效样本方向符合率都至少 90%，连续接收最大间隔不超过 250 ms。
结束时还需核对本轮起始实际模型与末次读回一致。
候选模型只有全部通过才保留，否则恢复测试前模型；取消也走同样的恢复。
画面当前方向只来自有效真实坐标，超过 300 ms 不再显示旧方向。
## 最小选区验证（2026-10-04）

当前用户要求先验证稳定选中与进度条。多级菜单和开机自启动暂不实施。

```sh
sudo sh display_session.sh guide --seconds 0 --live --selection-test --width-mm 220 --height-mm 160
```

PS_KEY0 开始本轮中、左、右三点宽松校准。校准应用后检查 10 秒真实有效注视，
成功便在同一 USB 会话中进入左、中、右三个选区；不上传历史模型，
失败也不恢复旧个人模型，调整后重新校准。PS_KEY1 在校准期间停止，
在选区页暂停/继续。PS_RESET 是硬件复位键，不用于开始。

本页测试水平三分区，命中范围覆盖屏幕高度，不代表精确二维定位。
三点坐标为中(0.5,0.4)、左(0.15,0.6)、右(0.85,0.6)，稍微错开高度，
用于排除原同一水平线可能影响模组二维拟合的问题；是否改善须实测。
边界两侧各 0.025 归一化宽度为中性区。连续稳定 0.2 秒后高亮，
继续有效注视 1.2 秒填满进度并确认一次；无效、越界、处理延迟超过
250 毫秒或采样间隔超过 250 毫秒清空待确认进度。只有稳定进入另一区
才重新允许确认，眨眼、暂停和一直看同一区不会解除已确认区的锁定。

时标来自板端原生解码时的 CLOCK_MONOTONIC，不是已核验的模组硬件
采样时钟。默认画面持续显示至明确停止，没有原诊断页的有限时长退出。
校准 CSV 保存，选区阶段不持续追加 CSV；两幅诊断 IR 图轮换，避免长期
运行造成捕获文件无限增长。该命令不安装或修改任何启动服务。

最小模式也不读取旧模型或导出新模型；成功条件是三点采样、固件计算
应用/退出均返回成功，且随后收到至少30个严格有效注视样本。这只允许
进入实际选区测试，不代表准确率验收；`changed` 为null，不声称模型字节
已核对。独立旧模型诊断读回仍存在部分长度下的帧解析问题，未在此修复。
`--locate` 是10秒图像/眼状态检查，不读写校准模型；HDMI真正显示白点后
才发送locate启动采集计时，屏幕同步显示剩余秒数。

本地控制边界测试与 ARM 编译通过；真人确认结果另见 report/verification.md。

五点对照可增加 `--calibration-points 5`，选区页仍只有左、中、右。
九点对照使用 `--calibration-points 9`，复用此前成功的九点坐标和顺序，
不恢复历史模型。2026-10-04 板上准备页已改为此对照；不自动开始采样。
当前三点和五点都出现采样接受后042e计算失败，尚未进入真人选区验收。
042e失败来自模组，发生在程序的应用后有效注视检查之前；不是外层精度
阈值导致。不能把该返回改成成功来放宽校准。只用横向数据的三点映射是
待验证方案，须核实重启后数据可用和独立左右中测试，尚未作为正式模式部署。

## 板端三点方向标定试验

```sh
sudo sh display_session.sh guide --seconds 0 --live --relative-selection --width-mm 220 --height-mm 160
```

PS_KEY0 连接后先进入实时距离检查页，调整好位置再按一次开始5秒倒计时，
跟随中、左、右三个同高度白点，每点2秒稳定、
6秒采样，通常约30秒。它读取模组当前实际注视流，以横向中位数作为
本轮三点锚，不调用OEM的开始/清空/采点/计算或模型读写命令，不把
完整屏幕校准失败改成成功。屏幕明确写“三点方向标定”。

每点至少60个可用横向样本，覆盖至少2秒；三个锚须按顺序分开，相邻
间距至少0.05，且大于对应两点MAD之和的3倍。反向坐标轴可识别。
当前一只眼有效即可，不按纵向坐标是否落在屏幕范围拒绝横向数据。
映射结果明确作为派生横向坐标，通过horizontal_gaze发送；不伪造纵向
注视坐标。映射越界不夹紧；过期/丢眼/边界中性区仍取消待确认进度。

标定成功后同一USB会话显示三区、高亮和进度条，沿用0.2秒稳定+
1.2秒连续停留、同区一次确认和换区重新允许确认。PS_KEY1暂停/继续，
PS_KEY0停止当前会话并重新连接到距离检查页；三点、选区和媒体页面继续显示距离。
锚点只存本轮进程内存，每次重做重新采样，不加载旧锚或上传旧模型。

该模式依赖模组当前能输出可用横向注视；设备内可能仍有既有模型。
没有恢复旧模型不等于已排除这种依赖。冷启动后数据可用性、新测试者
和新会话的效果尚未验证，不能据单轮结果宣称上电即用或替代OEM算法。
本地46项检查、ARM严格编译和方向策略C检查通过，板上准备页已恢复；
真实三区确认结果待记录。
