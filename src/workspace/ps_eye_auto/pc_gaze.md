# 电脑端三点眼动测试

`start_pc_gaze.bat` 打开电脑端眼动测试窗口。当前为 r7，标题含“人脸锚定与眼动保留”。它使用与 PS 相同的 `haar.c`、`auto_face.c`、`eye_tracker.c`；Python 负责摄像头和显示。配套 DLL、ARM ELF 和 BOOT.BIN 已重建，旧版本 ZIP 保留。

r7 用人脸框的平移/缩放来更新分析框，避免双眼模型框随眼球共同移动时抵消方向特征。校准门槛不变；它仍可能受人脸框抖动、阴影、反光和头动影响，实际效果需重测。说明见 [gaze_roi_motion_r7.md](report/gaze_roi_motion_r7.md)。

r6 改为保留每眼最近 16 个有效样本，少量跳点不再清空整批；抖动偏大时继续更新窗口。失败后保留参考值和抖动，提示具体眼睛、失败原因，可点击“重采失败点”从提示的点继续。若换了坐姿，先“清除校准”再重新开始。验证见 [calibration_recovery_r6.md](report/calibration_recovery_r6.md)。

r2 修正了旧固定阈值在偏暗眼图中选中大片阴影、再因面积过大而拒绝的问题。现在按眼框亮度分布选取暗部，并检查连通区域、形状和周围对比度。输出是虹膜/瞳孔暗部的估计中心，不是精确的瞳孔边界。验证见 [pupil_fix_r2.md](report/pupil_fix_r2.md)。

r3 将白点上移并向两侧拉开，校准改为逐眼积累、丢失后续采。r4 扩大模型眼区并跟随双眼框，r5 在共享 C 算法中加入每眼个人归一化、双眼一致性、短窗中值滤波和方向切换确认。眼部灰度先做 3×3 中值抑制孤立亮点和细碎睫毛，再进行暗部连通区域筛选。

## 启动

1. 双击 `start_pc_gaze.bat`。启动时不会打开摄像头。
2. 选择摄像头编号，通常是 `0`；外接摄像头可试 `1`。
3. 点击“启动摄像头”。正脸、均匀照明、摄像头固定在屏幕上方时再开始。
4. 先选好窗口大小（可按 F11 全屏），等状态变成“可以开始三点校准”，再点击“开始三点校准”。需要模型稳定定位双眼；暗部至少一眼有效即可开始。

如果程序提示 DLL 与源码不一致，关闭窗口后在 `ps_eye_auto` 目录执行：

```powershell
python tools\build_pc_gaze.py --gcc C:/mingw64/mingw64/bin/gcc.exe
```

程序要求 x64 Python、Tk 和 `tests/requirements.txt` 中的 OpenCV/NumPy。安装方式与 [PC_TEST.md](PC_TEST.md) 相同。

## 稳定处理

每只眼的三个参考值用 16 个样本的中位数计算，同时保存中位绝对偏差（MAD）。r6 用中间 12 个样本的跨度判断是否稳定，跨度不超过 24 才完成该眼采样；全部 16 个样本仍参与中位数/MAD。相邻参考间距至少 6，且大于相邻 MAD 之和的两倍，中点须在左右之间。重叠的数据仍不能通过校准。

运行时两眼各自映射到个人尺度：左侧约 -256，中间 0，右侧约 +256。双眼一致后取平均，使用最近最多 5 个、年龄不超过 500 ms 的样本做中值滤波；至少积累 3 个样本才判断方向。当前值与滤波结果必须落在同一区域，并连续确认至少两帧、累计至少 80 ms。

单帧跳变和方向边界会暂停方向与停留，但短窗历史保留。丢眼、双眼明显冲突、超出个人范围或运行采样间隔超过 250 ms 会清空滤波历史，校准保留。原始十字不做时间平滑，便于看到实际定位偏差；状态行的“归一化 原始值 → 滤波值”用于观察抖动。

## 三点校准

白色目标依次出现在左、中、右三处，横向为画面宽度的 8%、50%、92%，高度为距画面顶部 18%。每个点先累计约 2 秒有效等待，再为每眼分别收集 16 个样本。目标移动后再看下一个点；不要用鼠标点击目标，也不要转头追目标。

校准过程中：

- 顶部三个方向格显示当前校准点。
- 进度条先显示等待稳定，再分别显示 `画面左眼 n/16，右眼 n/16`。
- 一眼暗部无效时，该眼暂停、另一眼继续采样；模型眼对丢失时两眼都暂停。已完成的点与当前样本保留，恢复后自动继续。没有原来的 15 秒整轮超时。
- 人脸或眼框偏移超出跟随范围时暂停，回原坐姿、连续定位稳定后恢复。人脸框的小幅平移和 0.75–1.33 倍尺度变化会自动投影到当前 ROI；脸部尺寸、双眼间距、连线斜率不一致时不会跟随。若想换个位置，点击“清除校准”后重做。样本满 16 个但仍抖动时，程序逐个更新最近样本，进度不归零；已采好的另一眼等待补齐。
- 相机图像上黄色框是人脸，绿色框是有效眼区，红色框表示暗区特征无效，十字是暗区重心。
- “眼内位置”显示两只眼的横向归一化坐标，范围是 0–256。这些数值在看左、中、右时应有可重复的变化。
- 两眼诊断分别显示暗区比例、主暗部比例、局部对比度和阈值；无效时给出具体原因。完成校准点后显示“参考”和“抖动”，顺序为左、中、右；尚未采集的点显示 0。
- 校准未通过时，参考值和失败原因会保留。点击“重采失败点”后，保留该点之前的参考，重新等待 2 秒并重采该点及其后面的点；定位仍以原坐姿为准。若多次重采仍不通过，可清除后重做，并导出诊断记录排查。

出现“校准完成”后，观察方向格和状态行：

- 两只眼的归一化位置都更接近左侧参考值时显示 `左 LEFT`。
- 更接近中间参考值时显示 `中 CENTER`。
- 更接近右侧参考值时显示 `右 RIGHT`。
- 两眼结果冲突、暗区无效、眼对丢失或位置改变时显示“无效”，不累计停留时间。
- 方向确认后，左或右再保持至少 750 ms 产生一次事件。持续看同一侧不会重复；确认中间方向后再保持至少 350 ms 才重新允许事件。滤波和切换确认另有延迟，不能把总响应时间写成 750 ms。

模型先找人脸和眼框，`eye_tracker.c` 在随头部共同移动的校准 ROI 中计算暗区重心，再用个人参考映射方向。摄像头镜像时，校准顺序仍然有效。两只眼的原始坐标不同本身不代表错误，需比较各自校准后的方向。

## 失败时先看哪一项

| 现象 | 含义 | 处理 |
|---|---|---|
| 找不到双眼 | 人脸或双眼模型没有形成合格眼对 | 正脸、增大脸在画面中的尺寸、调整照明和摄像头距离 |
| 有眼框但红色 | 框内对比度或暗像素比例不满足固件条件 | 检查曝光、眼镜反光、睫毛阴影和框位置 |
| 三点校准失败 | 状态行指出哪只眼间距不足、顺序错误或抖动过大 | 点击“重采失败点”；换坐姿先清除；反复失败时导出诊断记录 |
| 白点停在一处 | 正在补齐某眼样本、更新抖动窗口或等待定位恢复 | 看两眼计数和提示；16/16 仍可能等待跨度收敛，无需反复点击开始 |
| 方向一直无效 | 双眼无效、不一致、位于方向边界或离个人校准范围太远 | 短暂漏检先等恢复；若已更换坐姿，再清除并重做 |
| 方向卡住 | 超过 1 秒没有新鲜图像 | 检查摄像头驱动；程序会自动清除方向 |
| 采样间隔过长 | 运行间隔超过 250 ms，无法持续确认方向 | 查看间隔数值，检查相机与主机负载；ARM 需单独测量速度 |

“PC 检测 xx ms”只表示电脑执行 C 模型的一次耗时，不是 Z15 Cortex-A9 的速度。导出诊断记录保存时间、方向、坐标、质量和错误状态；校准期间每帧记录，阶段切换和失败当帧立即保存完整状态，最多保留最近 2000 条。r7 还记录原始人脸/眼检测框，可与分析框比较。不自动保存或上传摄像头照片。

遇到红框或校准不成功，可点击“保存原图与诊断”，选择本地路径。它保存点击时选中的无标框 PNG 和同名 JSON，两者来自同一帧。这比窗口截图更适合排查。保存含本人图像，由使用者主动选择；程序不自动录制或上传。

## 当前边界

电脑窗口使用所选电脑摄像头的实际输入。测试通过不代表 OV5640 的图像、ARM 性能或板上链路已经通过。Haar 与暗部候选仍可能定位错误，平滑不会修正持续错误的中心。r6 修复的是采样容错、失败诊断和重试；没有新增连续真人成功率测量，需重新实测。
