# 完整项目思路

## 2026-09-30 眼控方案更新

用户提出：通过网口接收双眼坐标，网络不可用时由板端 PS 本地寻找双眼。后续眼控按“网口定位优先、PS 本地定位回退”组织。当前 r8-live-osd 仍是本地 PS 定位与独立 PL 视频/OSD，尚未实现网口坐标接收和来源切换；r8 实板验证仍待记录。

联网路径计划接收外部主机的双眼定位结果，由 PS 校验后接入板端眼控流程。断网路径继续使用 OV5640 与现有 PS Haar/眼部定位。两条路径共用的坐标约定、特征与校准接口需验证，不能仅因切换定位来源就假定旧校准仍然适用。PL 视频与 OSD 继续独立运行；显示暂留框不作为有效控制输入。

“双眼坐标”尚未冻结为眼框或中心点。如果复用当前眼内特征提取，需要左右眼 ROI 范围；仅中心点不能直接替代完整 ROI。外部主机是否分析同一 OV5640 画面、如何取得图像、帧号及坐标映射也待确定；另一台摄像头的坐标不能直接用作 OV5640 的像素位置。

切换策略拟同时检查网络状态和定位数据的新鲜度。断线或持续收不到有效结果时回退 PS；恢复后连续确认结果可用再切回。具体超时、恢复条件及校准处理尚未实现或实测。原方案的眼控倒立摆、脑控灵巧手、肌电灵巧手保留为项目规划，其余模块不因本次更新而视为已完成。

用户确认：参加 FPGA 设计大赛 AMD 自主选题初级组，使用正点原子 Z15，工程需要长期维护，使用 Trellis，开发者标识为 sds。

作品希望展示：同一块 Z15 如何接收多种人体输入，在明确的模式下产生可追踪的控制命令，再使机械设备执行。候选应用定位是多种输入方式的设备交互实验平台。实际服务人群、与已有方案的差异、应用价值证据仍需确定；不能直接写成已验证的医疗或康复产品。

## 功能地图

| 模式 | 输入与处理 | 演示结果 | 当前状态 |
| --- | --- | --- | --- |
| 眼控 | OV5640、固定眼部 ROI、相对位置特征、三方向标定与停留确认 | 当前先输出电脑串口；后续再适配倒立摆 | RTL、电脑工具、bitstream 已有，实物验证待完成 |
| 脑控 | 8 通道 EEG、屏幕 SSVEP 刺激、CCA 或频谱参考识别 | 灵巧手选择动作 | 待实现，设备协议和刺激参数未定 |
| 肌电 | sEMG、ADC 或数字接口、滤波与特征、阈值/迟滞 | 手张开/闭合，后续可扩展闭合比例 | 待实现，采集形式未定 |
| 脑状态 | 与模型定义一致的 EEG 窗口 | 情绪类别及疲劳曲线 | 原方案称情绪模型已有，未收到权重或验证证据 |
| 视觉 | 同一摄像头切换拍摄对象，少量预定类别 | FIST / OPEN / V_SIGN 等分类展示 | 候选扩展，未实现 |
| 音频与音乐 | 本地 PCM 播放、FFT、按播放样本位置调度时间表 | 手势、倒立摆参考轨迹、灯光同步 | 候选扩展，未实现 |

多模态在这里首先指多种输入模式可切换，并不等于同时融合三类信号。主动控制源一次只选一个。眼控与视觉复用同一摄像头；情绪/疲劳仅展示。第一版脑控是 SSVEP 目标选择，运动想象不是前提。

## 一场完整演示

冷启动进入空闲页，由板载按键选择模式。先看左中右使倒立摆改变参考位置，再注视 SSVEP 目标使手动作，再通过收缩/放松控制手。切到监测页查看脑状态，随后展示视觉分类，最后播放本地音乐并同步手、摆、灯光和频谱。退出时撤销旧控制权，设备按各自已经验证的策略待机。

这是完整构想，不是当前可运行流程。第一阶段只需建立相机、HDMI、眼控与一种执行端的闭环。

## FPGA 设计要体现在哪里

主线可展示像素流接收、时钟域跨越、灰度/ROI/特征流水线、方向判定状态机、停留门控、视频叠加、串口接口和时序约束。后续选择实际有收益的滤波、FFT 或特征算子进行 PS 与 PS+PL 同条件对照。

必须记录哪些环节运行在 PL，哪些在 ARM，哪些留在 Nano/STM32。算法窗口时间、传输时间、硬件计算时间、确认时间和机械响应分别测量，不把计算内核耗时写成整机响应。

## 第一版边界

- 一块 Z15、一块 HDMI 屏、一个 OV5640；实际附件库存尚未核对。
- 主流程为眼控倒立摆、脑控灵巧手、肌电灵巧手；不要求三种输入与两个执行器所有组合。
- 眼控是固定位置条件下的左/中/右，不承诺任意屏幕坐标。
- 肌电闭合比例不是测得的握力。手无位置反馈时不能报告到位精度。
- 音乐先用预编排时间表；FFT 展示真实音频频谱，不声称自动生成舞蹈。
- 原方案不纳入云端 LLM、手机求助、iCAN 电脑端控制、全部平衡闭环迁入 FPGA。
