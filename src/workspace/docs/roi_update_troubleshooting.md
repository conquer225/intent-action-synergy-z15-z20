# 换电脑后，眼框无法应用

电脑工具版本：2026.09.25-r2。适配现有 v2 `z15_screen_top.bit`，本次只更新 Python 工具。

## 这次截图说明了什么

截图显示相机 5640、就绪 1、故障 0，顶部却是“FPGA 未确认参数”。电脑图上的眼框和红蓝色块是本地预览，修改后立即变化，不能据此认为板子已接受参数。只有收到两个目标眼框的匹配回执，才显示“双眼参数已确认”。这也不等于识别准确或校准完成。

源码中有一个已确认的更新问题：板子逐个接收眼框，如果新眼 1 与板上旧眼 2 重叠，就拒绝写入，且不发回执。旧工具等待眼 1 确认后才发眼 2，因此即使最终两个框不重叠，也可能卡住。串口重连和“返回预览”均不清除板上眼框。仅凭截图不能排除串口发送或固件不匹配等其他原因。

新版先正常发送。若等待 3 秒没有回执，会把眼 1 临时挪到不占用目标框的角落，确认后写入目标眼 2，再写回目标眼 1。若角落也与旧眼 2 冲突，会换角落，最多尝试四处；仍无确认就停止。部分更新失败时不会自动恢复未知的旧坐标，HDMI 可能留着临时框；须重新应用成功后再校准。

## 队友执行清单

1. 关闭旧电脑工具和其他占用串口的软件。将 `Z15_Screen_PC_20260925_r2.zip` 复制到正在连接板子的电脑，完整解压到新文件夹，别只复制一个 Python 文件。
2. 若该电脑已经运行过旧工具，直接双击解压目录中的 `tools/start_screen_monitor.bat`。若提示缺少 serial，在解压目录打开终端执行 `python -m pip install -r tools/requirements.txt`，然后重开。需要带 tkinter 的 Python 3。
3. 检查窗口标题包含“参数诊断版 2026.09.25-r2”。若没有，仍在运行旧文件。
4. Z15 保持供电，OV5640 接 P2、HDMI OUT 接显示器，J23 的 PL UART USB 接现在这台电脑。电脑工具不下载 FPGA 固件。若板子此前断电，需确认重新启动后仍运行 v2 固件；没有固化到 Flash 时需通过 JTAG 重新下载。
5. 点击“刷新”，选择 J23 对应 COM 口，再点“连接”。用户截图中为 COM15，但换电脑后端口号可能变化。应出现相机 5640、就绪 1、故障 0。
6. 点击“返回预览 / 重新设置”，再点“取图（约 7 秒）”，等整幅快照出现。保持相机和坐姿不动，分别框住两眼。快照不是连续视频，人移动后应重新取图。
7. 如果相机、坐姿与最后截图一致，可先照下面的数值填写，只验证参数能否下发；它们不是已验收的眼控参数。

| 参数 | 眼 1 | 眼 2 |
| --- | --- | --- |
| X | 382 | 440 |
| Y | 152 | 147 |
| 宽 | 43 | 46 |
| 高 | 30 | 36 |
| 暗阈值 | 45 | 45 |
| 亮阈值 | 61 | 61 |

8. 点一次“应用双眼参数”。等待最终成功或失败提示，期间不要改数字、拖框或断开。通常几秒；完整超时流程可能接近 25 秒。HDMI 框暂时去角落是自动挪框过程。
9. 成功时，日志出现两个目标眼框各自的“收到匹配 RCFG”和“双眼参数已确认”，HDMI 预览框应移到目标位置。确认后如果框仍不动，请保留日志和 HDMI 照片；不要据此认定显示路径已正常。
10. 若失败，点击“复制诊断日志”，把复制的全文发来。日志会给出发送的坐标、哪个回执缺失、是否进入临时挪框。先解决下发问题，再调整阈值。

参数确认成功后，仍须下方“眼 1：有效、眼 2：有效”、相机持续出帧，才能点击“开始 HDMI 三点校准”。仅收到回执不会绕过有效性检查。看 HDMI 白点，头不转，依次看左、中、右；完成后再实测三个注视区域。完整说明见 [screen_gaze.md](screen_gaze.md)，原始灰度检查见 [gray_inspection.md](gray_inspection.md)。

## 验证范围

已在电脑模拟串口中复现旧框阻挡新框，验证自动挪框恢复、角落冲突重试、无回执停止、局部失败、编辑、断连和发送异常。没有在用户当前连接的另一台电脑或板子上远程执行；本更新不改变眼部识别算法，也不提供新的真人准确率结论。
