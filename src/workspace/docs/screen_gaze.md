# Z15 屏幕左、中、右眼控使用说明（v2）

本版对应 `z15_screen_top.bit` 和 `screen_monitor.py`。摄像头固定在 HDMI 屏幕上方，镜头朝向使用者；人正对屏幕坐好，用眼睛看屏幕左、中、右三个区域。两只眼睛都参与识别。电脑负责第一次取图、框选双眼和查看串口，实际识别、校准、停留确认和 HDMI 画面都在 FPGA 内运行。

代码、仿真和可下载固件已经完成，尚未连接实物测试。下面的效果图来自 RTL 仿真，不是上板照片；对焦、光照、真实识别率和显示器兼容性需要首次上板核验。

## 1. 使用时是什么样

校准完成后，HDMI 显示 LEFT（左）、CENTER（中）、RIGHT（右）三个大区域。看左区域，左框变绿；看中区域，中框变绿；看右区域，右框变绿。第一次测试先看各框里的目标点。两个区域边界附近允许拒识，不表示连续坐标定位。

![运行画面，RTL 仿真示例](../report/screen/hdmi_run.png)

绿色表示当前有效识别。看左或右持续约 0.75 秒后，进度条完成，电脑日志显示一次“确认 #序号：左/右”。确认后一直盯着同一侧不会重复触发。看中间至少约 0.35 秒释放，然后再看左/右才能产生下一次确认。识别方向还需要连续三个有效帧，所以从眼睛转动到确认的总时间会比 0.75 秒稍长。

中间也是一个可识别区域，在本阶段承担释放作用，不发确认事件。闭眼、看不清双眼、双眼方向不一致或检测到位置变化时，输出无效、停留计时清零。重新睁眼不等于已经释放，仍需回中。

## 2. 准备与接线

需要 Z15、正点原子 OV5640、HDMI 显示器与线、Xilinx 兼容 JTAG 下载器、PL 串口 USB 数据线及原配 12V 电源。摄像头在屏幕上方居中固定，镜头朝人，不朝屏幕。屏幕接 FPGA 的 HDMI OUT；电脑可用自己的屏幕显示设置工具。

```text
             OV5640（朝向人）
                    │ 18 针摄像头连接
                    ▼
电脑 USB ─ JTAG下载器 ─ J18  Z15  HDMI OUT ─ HDMI显示器
电脑 USB ─ 数据线 ──── J23   │              左  中  右
原配12V电源 ────────── J1    P2                 ↑
                                           人看这里
```

断电后接线和设置跳线。下表针对已查到的 Z15 底板 1V1 原理图；板上连接器外形不同时，以对应修订的原理图核对。

| 部位 | 接法 |
| --- | --- |
| P2 / CAMERA | OV5640 的 18 针接口接这里，1 脚对 1 脚，不能错位或反插 |
| Bank34、Bank35 | 本工程都需要 1.8V。1V1 原理图的三针 J4、J3 各短接 2–3。若实物是六针座，不套用这个针号 |
| BOOT_CFG | 开关 1、2 都拨到 ON，使用 JTAG 启动模式 |
| J24 | 两个跳线帽分别短接 1–3、2–4，使 PL UART 连接 USB 串口芯片 |
| J18 / JTAG | 接 10 针下载器排线，下载器 USB 接电脑 |
| J23 / PL UART | Type-C 数据线接电脑；不要接成 PS UART |
| HDMI OUT | HDMI 线接显示器输入，显示器菜单切到该 HDMI 输入 |
| J1 / DC | 原配 12V 适配器供电，接好后打开电源开关 |

USB 串口线不负责整板供电。不要用普通杜邦线随意重排 P2 引脚。相机模块自带参考时钟，本工程无需额外接 XCLK。

## 3. 在 Vivado 中下载新版固件

本机完整工程位于 `D:/fpga/z15_multimodal`。若使用 ZIP，在较短的英文路径解压，下面路径相应替换为解压目录。

1. 打开 Vivado 2023.1，点 **File → Open Project**。
2. 打开 `D:/fpga/z15_multimodal/local/screen_vivado/z15_screen.xpr`。
3. 确认标题是 `z15_screen`，顶层是 `z15_screen_top`。原来的 `project_1.xpr` 是空工程，这次不使用它。
4. 左侧 **PROGRAM AND DEBUG → Open Hardware Manager**。
5. 点 **Open target → Auto Connect**。
6. Hardware 树中找到名称包含 `xc7z015` 的器件，右键 → **Program Device**。
7. **Bitstream file** 选择 `D:/fpga/z15_multimodal/report/screen/z15_screen_top.bit`；**Debug probes file** 留空。
8. 点 **Program**，等待成功，再等约 5–10 秒供相机初始化。

固件已经生成，不需要先运行综合或生成 bitstream。下载是 JTAG 易失性配置，断电后需要重新下载；本阶段不烧写 Flash，也不需要 SD 卡、PYNQ 或 HWH。

初始化完成后，HDMI 应显示摄像头灰度预览和 `SETUP ON COMPUTER`。本版用户 LED 高电平点亮：`led[0]` 表示相机就绪，`led[1]` 表示有效方向；最终以电脑状态为准。旧 v1 的灯逻辑相反，不能混用旧说明。

## 4. 运行电脑设置工具

1. Windows 开始按钮右键 → **设备管理器 → 端口（COM 和 LPT）**，找到 PL UART 的 COM 号。若多个端口难以区分，观察拔插 J23 的 USB 线时出现/消失的端口。
2. 关闭占用同一 COM 口的串口助手。
3. 开始按钮右键 → **终端**，在 PowerShell 逐行执行：

```powershell
cd D:\fpga\z15_multimodal
python -m pip install -r tools\requirements.txt
python tools\screen_monitor.py
```

这些命令不要输入 Vivado 的 Tcl Console。当前电脑已验证 tkinter 和 pyserial；换电脑需要带 tkinter 的 Python。

4. 新窗口点 **刷新**，选 COM 口，点 **连接**。工具固定使用 115200、8 数据位、无校验、1 停止位。
5. 检查下方“相机 5640 / 就绪 1 / 故障 0”。未校准时显示“设置、识别无效”正常。

## 5. 让摄像头看清两只眼睛

1. 正对屏幕坐好，保持头部位置，点击 **取图（约 7 秒）**。
2. 等快照出现。它是 320×240 灰度图放大两倍，界面坐标对应原始 640×480 图像；不是实时电脑视频。需要更新时再次取图。
3. 图像中应同时看清两只眼睛的虹膜与眼白。眼睛横向开口至少约 24 个界面像素，只是起步条件，不保证一定可识别。
4. 如果只看到很小的整张脸，先调整人与屏幕距离、摄像头角度和镜头焦点，再取图。若固定在屏幕上方、正常注视屏幕时仍拍不清双眼，当前镜头成像条件就未满足，软件调阈值无法补回细节。

用均匀正面光，避开背光和眼镜强反光。普通 OV5640 常拍到的是虹膜连同瞳孔的暗区，因此本工程按“相对暗区特征”识别方向，不宣称精密瞳孔边界检测。不要用转头放大差异来代替眼球转动。

## 6. 分别框选双眼，调整阈值

1. 点右侧 **框选眼 1（按画面从左到右）**，在图片上按住鼠标左键拖出矩形，圈住画面左边眼睛的虹膜和两侧眼白。
2. 点 **框选眼 2（按画面从左到右）**，同样框住另一只眼。
3. 两框不能重叠。避开眉毛、黑镜框和大片皮肤阴影；也不要把眼白裁掉。左右按画面顺序命名，无需区分解剖学左右眼。
4. 默认暗阈值 70、亮阈值 140。勾选 **阈值预览：红色暗区 / 蓝色亮区**。红色应主要覆盖虹膜暗区，蓝色应包含眼白。
5. 红色连到眼框边缘、睫毛或大片阴影时，缩紧眼框或适当降低暗阈值；虹膜基本不红时适当提高暗阈值。眼白没有蓝色时适当降低亮阈值；大片皮肤也蓝时调整眼框、光照或提高亮阈值。修改数值会立即更新当前快照的颜色覆盖。
6. 点 **应用双眼参数**，等待“FPGA 已确认两个眼框”。工具逐个发送并等待硬件回执，不会只因点击按钮就当作成功。
7. 查看下方 **眼 1：有效、眼 2：有效**。眼框坐标与阈值改动后，必须再次应用。只有两眼均有效、相机持续出帧且参数已确认时，校准按钮才能使用。

每框允许宽 24–160、高 12–96，必须完整位于 640×480 内。暗阈值至少 8，亮阈值至少比暗阈值大 16，最大 248。颜色覆盖只帮助看阈值分割；实际有效性还检查暗区形状、面积、对比度和边缘污染，所以“有红蓝色”不必然等于有效。

默认眼框只是初值，不会自动寻找人脸或跟随眼睛。首次调试建议让旁边的人点击取图和检查状态，使用者持续保持坐姿，避免低头看电脑导致眼框错位。

## 7. 自动完成屏幕三点校准

1. 两眼有效后点 **开始 HDMI 三点校准**，将视线转回 HDMI 屏幕。
2. 屏幕左框变为黄色，并显示白色目标点。眼睛看白点，头保持正对屏幕。
3. 每个目标先等待 2 秒，让视线稳定，再收集 16 个连续有效且稳定的双眼样本。不要看到进度条暂时停止就转头。
4. 完成左侧后自动切到中间，再自动切到右侧。眼睛依次看新的白点，期间不用再点击电脑。
5. 完成后进入 `RUN`；若三个注视位置的特征太接近、次序不成立，或某一目标 15 秒内未完成采样，会显示校准失败。

![左侧校准画面，RTL 仿真示例](../report/screen/hdmi_calibration.png)

相机图像是否左右镜像由校准自动吸收，不需要手动翻转方向。每个人、每次移动镜头或坐姿明显改变后，都应重新设置和校准。校准与眼框保存在运行寄存器，断电、复位或重新下载后需要重新应用参数及校准。

## 8. 第一轮怎么测试

先测试区域识别，再测试确认事件。下列是待执行步骤，不是已经测得的成绩。

| 操作 | 应观察到的行为 |
| --- | --- |
| 看中框目标 | CENTER 变绿，电脑识别为“中” |
| 只转眼看左框目标 | LEFT 变绿；持续停留后日志出现一次“确认：左” |
| 继续看左约 3 秒 | 不重复确认 |
| 回中约 1 秒，再看右约 2 秒 | RIGHT 变绿，出现一次“确认：右” |
| 闭眼或遮住一只眼 | 方向无效，无新确认；睁眼后先回中再试 |
| 明显移开头部 | 应失效或提示回到原位；回到原位后重新检查 |
| 运行中点取图 | 暂停有效输出；约 7 秒传完后恢复，不能把取图停顿算成识别延迟 |

左右各重复 10 次，中间穿插回中，记录成功、误判、拒识和确认时间。随后保持正视或闭眼各观察一分钟，记录误确认次数。结果填入 `report/screen/board_test_template.csv`，不要把仿真结果填成真人成绩。

若左右不能区分，先检查真实图像与两眼特征变化，再调整 ROI、焦点或坐姿并重新校准。当前算法使用相对暗/亮区水平位置与双眼一致性，亮区会受到光照和眼皮影响；它不能支持自由转头，也不会得到精确屏幕坐标。

## 9. 常见状态与处理

| 现象 / HDMI 文字 | 含义及下一步 |
| --- | --- |
| HDMI 无信号 | 核对 HDMI OUT、显示器输入、下载成功；输出为 640×480 / 60 Hz |
| WAITING FOR CAMERA | 查看芯片 ID、就绪和故障；断电核对 P2 方向、供电和 Bank 电压 |
| 电脑提示旧版固件 | 下载的是 v1；换为 `report/screen/z15_screen_top.bit` |
| 取图超时 | 工具会断开；检查相机数据、串口和板卡，复位后重连、重新应用参数 |
| EYES NOT CLEAR | 至少一只眼不满足质量条件；取图检查两眼框、光照、焦点、红蓝分割 |
| MOVE BACK TO POSITION | 亮区位置或双眼间距偏离校准位置；先回原位，必要时重校准 |
| HOLD STILL: SAMPLING | 正在收集样本，继续盯白点，别转头 |
| CALIBRATION FAILED | 返回预览、重新应用参数，再校准；三个方向不能靠相同视线采样 |
| LOOK INSIDE A TARGET | 视线处于分类边界或两眼分类不一致；先看框内目标 |
| CAMERA FRAME LOST | 超过约 250 ms 无完整样本；检查采集链路 |
| LOOK CENTER TO REARM | 上一次已确认，看中间释放后才能再次确认 |
| 返回预览后校准按钮灰色 | 重新应用双眼参数，等待两眼有效和硬件确认 |
| 两个新眼框不重叠但应用超时 | 大幅移动眼框后，新框可能暂时碰到板内上一次的另一只眼框。复位板卡、重连工具，再应用新参数；复位后需要重新校准 |

## 10. 文件、串口与维护

| 内容 | 相对维护根目录的位置 |
| --- | --- |
| 新版工程 | `local/screen_vivado/z15_screen.xpr` |
| 新版 bitstream | `report/screen/z15_screen_top.bit` |
| 电脑工具 / 协议 | `tools/screen_monitor.py`、`tools/screen_protocol.py` |
| RTL / 测试 | `src/screen/`、`sim/screen/` |
| 构建证据与限制 | `report/screen/verification.md` |
| 成对源码与产物哈希 | `report/screen/build_manifest.json` |

串口状态示例：

```text
SCR L V1 F3 M4 C7 P00 T0 H0 G0 A1 X70 Y71 E0001 DL S0 I5640 R1 !0
```

`SCR L/C/R/I` 是左/中/右/无效；`V` 是有效位；`F` 是双眼有效掩码（3 表示两眼有效）；`M` 是模式（0 设置、1/2/3 校准、4 运行、5 失败）；`C` 是校准掩码；`P` 是采样数；`T` 是等待稳定结束；`H` 是原因；`G` 是进度；`A` 是可再次确认；`X/Y` 是两眼相对特征；`E` 是事件序号；`D` 是上一次确认方向；`S` 是样本中断；`I` 是芯片 ID；`R` 是相机就绪；`!` 是初始化故障。数值字段按十六进制表示。`D` 会保留上次方向，必须结合 `E` 变化与运行状态判断新事件。

`a` 开始自动校准，`v` 返回预览并清除校准，`x` 清除校准，`p` 请求快照。二进制 ROI 和 ACK 合约见 `.trellis/spec/hardware/screen-contract.md`。普通串口助手不适合解码混合的快照流；日常使用提供的工具。

重新构建与验证，在维护根目录运行：

```powershell
& 'D:/vivado/Vivado/2023.1/bin/vivado.bat' -mode batch -source build/screen/build.tcl
& ./build/screen/test.ps1
& ./build/screen/test_pipeline.ps1
python -m unittest discover -s sim/screen -p 'test_*.py' -v
python tools/screen_manifest.py
python tools/package_screen.py
```

原来的 `src/eye`、`report/eye` 和 v1 ZIP 是历史版本；新版仍复用其中的 UART、SCCB、帧缓存与跨时钟握手模块。不要把两个版本的全部 RTL 随意加入同一个 Vivado 工程，因为两版使用不同的摄像头 ROM。
