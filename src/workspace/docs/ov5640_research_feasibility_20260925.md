# OV5640 屏幕三区域眼控：科研证据与实施边界

日期：2026-09-25。快速研究简报，使用 AI 辅助检索、原文核对与工程分析。本文不是系统综述，也没有新增本项目实测成绩。

## 结论

保留 OV5640，继续开发固定坐姿的屏幕左、中、右识别，有研究依据。[1–4] 现有失败不足以推出“OV5640 不能用于眼控”：一方面，可见光摄像头的屏幕注视估计已有研究；另一方面，也找到相机型号及文献链接指向 OV5640 模组的注视区域分类论文。[1–3]

但本次没有核验到“原装正点原子 OV5640、Z15、当前 VGA/PL 设计、无需红外、固定头纯眼球转动”的同条件成功论文。三项问题必须分开：传感器能否提供信息、算法能否利用信息、算法能否在 Z15 上实时运行。文献主要支持前两项，板上部署仍需实现与验收。

## 检索与核对方法

研究问题：在 OV5640 固定于 HDMI 屏幕上方、双眼成像、初期固定坐姿的条件下，是否有足够科研依据支持继续开发三个屏幕区域的分类？

检索包括 OV5640 与 gaze tracking / eye tracking / pupil detection 组合；普通 RGB 注视估计检索定位 MPIIGaze、GazeCapture；传统定位方法检索 Timm / Barth / eye centre / gradients。纳入出版商、CVF 正式会议页面、作者大学存档和作者开源仓库。区分注视区域、瞳孔定位、疲劳/闭眼识别；后两者不能直接替代屏幕注视证据。

完整下载并提取 [1][2][4] 的 PDF，查看 MPIIGaze p7、GazeCapture p7、Timm p4 的实验图表。论文 [3] 核对出版商 HTML 全文，PDF 请求受阻。Semantic Scholar API 返回 429，记录为 S2-API-UNAVAILABLE；身份由正式会议/出版商/大学页面与原文核对。没有执行完整 Scopus/WoS、撤稿或利益冲突数据库排查，不把未查项目写成通过。

## 几个容易误读的地方

1. [3] 的 99.6% 允许邻近区域也算正确，例如真实10区时6–14区可计正确；应引用严格率92.8%，且不能冒充本项目成绩。
2. [3] 用过 OV5640 相关模组，不等于用过原装正点原子 P2 模组。论文有红外成像配置，也没有给出可直接套用的拍摄距离或滤片改装步骤。
3. [3] 可见光 CAVE 的77.7%来自另一数据集、另一实验任务，不能据此计算红外带来的提升幅度，也不是 OV5640 可见光测试。
4. [2] 的10–15fps对应缩小网络在iPhone6s上的整体速度估计；完整网络表格精度不能与缩小网络速度无条件拼成一个性能承诺。
5. [1] 跨数据集误差明显变大，说明换摄像头、光照和人群后需本地验证。所有结果都不能推出“换成神经网络就自动准确”。

## 为什么现有实现没有达到这些结果

本地 `src/screen/relative_eye.sv` 在手动矩形内累计所有暗像素和亮像素，再使用面积、包围框、触边、对比度检查及质心差。它没有实现 [1–3][5] 中的人脸/眼部定位、[4] 的梯度候选选择，也没有独立连通区域或可靠的人眼身份判断。用户照片中的大面积红色表示皮肤阴影也被暗阈值选中；背景有可能满足相同统计条件。

当前采集为640×480，快照为320×240放大。眼部成像像素、对焦、曝光、镜片反光和取景位置必须先测。提高输出分辨率只会在原来细节被采样丢失时可能有帮助；无法恢复失焦/遮挡信息，也会增加带宽和存储需求。

因此当前优先问题是检测算法与成像条件，尚没有证据要求立即淘汰 OV5640。

## 建议的工程路线（尚未实施）

第一步保持 OV5640 接 Z15，从实际相机保存未覆盖红蓝色的原始眼部样本。采集分开录制的左/中/右、闭眼、头部移动、背景及眼镜反光，评估曝光和清晰度。训练/调参数据与验证数据按录制段分开；验证泛化时按人分开，避免连续近似帧同时出现在两边造成虚高。

第二步先在电脑离线比较两种候选：眼部范围内的梯度/轮廓候选与相对位置法；小型、个体校准的三区域分类模型。输入仍来自 OV5640，电脑用于选算法而非把板上实时识别宣称为已完成。当前115200串口约7秒快照只适合少量调试样本，连续采样需要新增存储或更快数据通路。

第三步依据离线结果决定板上结构：PL负责采集、图像预处理和HDMI；轻量检测可评估继续放PL，复杂定位/分类可评估PS与PL协作。Z15是Zynq平台，但当前工程没有PS图像通路；采用PS需要新增工程，不能只把Python复制上板。不要直接承诺把完整VGG/iTracker塞进当前RTL。

现有布局布线报告记录 LUT 5865/46200、BRAM49/95、DSP0/160，说明资源并非已用尽，但不构成任何新模型能放下或达到实时帧率的证据。ROI缓存、行缓存和定点运算可以作为评估方向，最终由资源/时序和实测决定。

验收至少分开报告左中右正确、误判、拒识以及无眼背景误确认；用相同光照/距离比较，另测戴眼镜、轻微头动及更换使用者。分类边界附近应允许拒识。屏幕尺寸与使用距离未定，不能从论文平均角误差直接推算本项目三区域正确率。
