# Z15＋Z20 无线视觉演示使用说明

本版按用户批准的四模式计划实现。电脑负责流体、三维声谱和相对深度渲染，Z20 通过 USB Wi-Fi 接收 JPEG，再由唯一的 HDMI 程序显示；NPU 页在 Z20 本地绘制。最新修订恢复 Z15 原四个信号页面，Z20 增加麦克风／WAV 输入。音乐由明确操作启动；声音分类采集不会把麦克风回放到喇叭。

## 当前可以检查什么

电脑浏览器、真实录音 FFT、声音模型整数推理、JPEG/TCP 回环和历史相机帧深度流程已有离线验证。Z15 原显示类已实际构造并绘制新增菜单，安装器经过临时目录安装、启动摘要更新和逐文件回退检查。

2026-10-27 已在领航者实板完成 USB Wi-Fi、ARM JPEG 解码、真实相机取帧和 PL 整数核对。Z15 已从 COM18 登录、备份安装，157项文件摘要和脑电/共存引用一致。临时电脑热点为192.168.137.1，Z15为192.168.137.200，Z20为192.168.137.91，ESP32为192.168.137.118；这是当时的 DHCP 地址。后续用户确认双屏可见，原生眼控完成三点检查并观察到流体左右操作；完整四模式与机械动作验收仍待完成。用户随后撤下板卡，最新页面与声音输入修改采用离线验证，不能沿用旧板测结论。见 `report/feedback_offline_20261027.md`。

候选声音模型的分类质量与PL数值一致性分别报告；此前按源录音分组的准确率约52.3%。最新十分钟目标运行的显示测量598.36秒，平均6.807次/秒，控制ACK P95约68.9毫秒，每个区间有新快照；10次/秒性能验收未通过。该轮并未全程运行Z15菜单，不代替最终整套彩排。空间展示采用左相机单图输入，原双目测距保留严格配对条件。ESP32同网有间歇断连，执行器保持未使能。

## 包和运行条件

JPEG 库也已在官方根文件系统的 ARM QEMU 中运行：Python3.7.6、NumPy1.17.0，连续20次解码正确、损坏输入拒收、本地NPU页面绘制通过。记录见 `report/visual-arm.json`；这是用户态兼容性检查，未访问真实DMA或HDMI。

本轮离线修订包为 `artifacts/z15-z20-feedback-offline-20261028.zip`，旧 `z15-z20-wireless-visual-candidate.zip` 保留作版本对照。解压到电脑和 Z20 的独立目录；Z15 需要其中的 `z15`、`z20_compute`、两个安装器。包内没有 FPGA 镜像，不会改启动项或在启动时自动播放声音。更新器识别已记录的旧展示版本，支持更新现有私有配置并成对回退；未知源码版本仍在写入前拒绝。

Z20 需运行已核对的领航者 CLG400 Linux／PL，保留相机观察器、NPU 和独立显示内存。相机仍接原来已验证的 J3。启动器要求 UIO 名称 `navigator-mlp`、`navigator-npu-dma`、`z20-video-observer`，底层显示适配器继续核对显示环预留内存。当前方案无需改 Z15 FPGA 或脑电模型。

电脑使用已准备的 Python 环境：

```powershell
D:/fpga/z15_multimodal/integrations/z20_compute/build/reconstruction-venv/Scripts/python.exe
```

包内视觉脚本、Three.js、着色器、贴图、声音录音及 YOLO26m 深度权重均已本地保存。电脑还需已有 Chrome、Playwright、PyTorch、Ultralytics、OpenCV；演示时不下载依赖。新电脑先准备好这些依赖，不能依靠现场联网安装。

## 先在电脑上离线预览

当前无需板卡。在解压目录运行：

本机原工程可直接双击 `start_visual_offline.cmd`；它使用已经准备好的电脑环境。解压包使用下方脚本指定同一环境：

```powershell
./START_OFFLINE.ps1 -Python 'D:/fpga/z15_multimodal/integrations/z20_compute/build/reconstruction-venv/Scripts/python.exe'
```

会打开 Chrome。使用底部按钮或左右方向键、Enter、Escape选择四个模式；Enter在模式内返回。进入 NPU 后，左右键切换疲劳／情绪／声音分类。流体每次左右注入随机改变颜色、力度、半径和少量位置；方向保持对应左侧／右侧。关闭浏览器结束，状态写入 `run/offline/report.json`。

声音分类页点击“录一秒声音”，允许电脑麦克风，然后现场拍手、吹口哨、敲击，或让手机在麦克风旁播放。收齐一秒样本后自动提取40项特征并提交；页面显示本次窗口与结果。可以“导入 WAV”（十秒以内、16位 PCM），也可在“备用录音”选择拍手／口哨／敲击。默认候选模型只区分这三类，误分类照实显示。麦克风在电脑端，接板后分类在Z20 PL执行；离线排练使用软件整数参考。

离线的疲劳和情绪使用 LEMON 记录的分类器特征，不生成真人状态标签；界面分别标注记录回放及疲劳教师候选模型。新鲜网络输入可优先显示，真实 Z15 采集到特征再到新页面的完整链路留待接板验证。软件／NPU耗时比较同一输入、同一预测调用范围，包含输入量化，排除采集和网络；未接PL时不显示实测加速倍数。

原四页也可单独在电脑预览：解压包中进入 `z15_preview`，用已准备的 Python 执行 `python preview_signals.py`，浏览器打开 `http://127.0.0.1:9130/`。四个页签依次是疲劳、情绪、脑电与音乐联动、音乐音频分析。默认静音；点击“启用音乐预览”后，进入音乐联动页，连续记录结果满足原选曲规则才播放。音乐音频分析使用同一曲目与播放位置。此预览不控制硬件。

离线窗口标题区显示“离线回环联调”，NPU后端显示软件整数参考。它没有真实眼控输入、无线链路或实板HDMI输出。空间模式使用包内历史相机帧，不能用于验证“重新拍摄”的实物动作。

## 现场接线与无线

Z15 接原菜单屏，Z20 接 HDMI 展示屏和 USB Wi-Fi。电脑、Z20 加入 Z15 原热点，保留原 S3 配置。开发和验收均拔掉网线。热点必须允许客户端互访。

本次联调为保留电脑现有联网，采用临时电脑AP，Z15暂时切为客户端；没有修改原AP配置文件或禁用其开机服务。Z15更新持久保存，临时网络在重启后需重建。恢复Z15原热点可在板端运行 `sudo sh /home/xilinx/z20_visual_update_20261027/restore_ap.sh`，这会中断当前连接；原热点地址为192.168.50.1。Z15的PS串口是J14，本机当前COM18、115200；对应1V1原理图，SD启动BOOT_CFG两位均OFF，修改后断电重启。

本次适配器为 `0bda:b733 / RTL8733BU`。匹配 `5.4.0-xilinx-v2020.2` 的驱动已经实际构建并正常加载；包内 `drivers/8733bu-navigator-20261027.ko`、`drivers/build-result.json` 保存模块与构建摘要。仅在内核版本和模块 vermagic 匹配后手动 `insmod`，不使用强制加载。`sources/rtl8733bu.tar.gz` 保存驱动源码。包不会自动加载模块或改启动项。

取得 Z20 的无线 IPv4 后，在解压目录生成一次私有配置：

```powershell
python run_visual_demo.py init-config --host 192.168.50.20
```

地址只是格式示例，须换成实际地址。生成的 `private` 文件夹复制到电脑和 Z20 同一解压目录；其中 `token.txt` 用于 Z15 安装。不要把该文件夹发到公开仓库。

## 启动次序

Z20 先运行只读检查：

```sh
python3 run_visual_demo.py doctor
```

确认 USB Wi-Fi 对应地址、匹配 UIO 和原显示程序已退出，再启动：

```sh
sh START_BOARD.sh
```

此命令前台运行，Ctrl+C 走原资源释放流程。不要同时启动旧 headless 或其他 HDMI 程序。启动器不重启、不加载 FPGA，也不停止原设备服务。

电脑进入解压目录，用上述已准备的 Python 执行：

```powershell
python run_visual_demo.py pc
```

或 `./START_PC.ps1 -Python '实际的python.exe路径'`。界面只访问本机，画面回传走 Z20 的无线地址。初始捕获 960×540、质量 70、目标 12 次/秒；连续五秒实收不足 10 次/秒时，降到 640×360、质量 65、目标 10 次/秒。目标值不代表板端已达到，需检查实际接收和显示计数。

## 安装 Z15 菜单

先在真实 Z15 上核对当前运行目录，保留原启动方法。安装器使用现有的成对完整性事务，要求显示、媒体网页和采集进程按原方法退出，避免更新一半的进程继续运行。它不会自行杀进程。

```sh
python3 install_visual_z15.py \
  --media-root /实际媒体目录 --brain-root /实际脑电目录 --eye-root /实际眼控目录 \
  --host 192.168.50.20 --token-file private/token.txt
```

先输出预览，版本或摘要不匹配会在写入前拒绝。核对后，同一条命令加 `--apply` 安装；记录输出的 `INSTALLED_BACKUP` 路径，恢复原启动方式。不要用参考副本覆盖未知现场版本。

回退使用相同三个目录：

```sh
python3 install_visual_z15.py \
  --media-root /实际媒体目录 --brain-root /实际脑电目录 --eye-root /实际眼控目录 \
  --rollback /安装输出的备份目录
```

新增菜单沿用原眼控呈现确认、停留和退出规则。“多媒体→音乐与 Z20→Z20 展示”进入模式选择。进入外部展示时先撤销设备使能；原手机主页/强制停止仍可返回。要再次使用灵巧手或倒立摆，必须重新进入并启用。

| 模式 | 左区 | 中区 | 右区 |
|---|---|---|---|
| 选择模式 | 上个模式 | 进入 | 下个模式 |
| 流体 | 左侧注入 | 返回选择 | 右侧注入 |
| 声谱 | 上段录音 | 返回选择 | 下段录音 |
| NPU | 上一分类任务 | 返回选择 | 下一分类任务 |
| 空间 | 拍摄并生成 | 返回选择 | 切换原图/深度/三维 |

初次进入空间模式会取得一帧新鲜相机图；再次左区拍摄使用新的模式版本。历史输入只用于离线测试，正式入口拒绝相机文件回放参数。深度坐标为中位数归一化的相对单位。

Z15 图像只循环霓虹轮廓、彩色拖影、运动分析，对应原硬件编号 1、2、3。PL_KEY1循环疲劳、情绪、脑电与音乐联动、音乐音频分析四页；音乐PCM与FFT恢复原生命周期。空对象状态与清理判断仍保留，显式关闭某页也不会因读取空音频对象退出显示。运动背景压暗的RTL已离线仿真，新比特流构建尚未通过，当前包不包含这份固件。

设备页先选择“启用灵巧手／启用倒立摆”，收到确认后才出现动作。中区停止并返回。界面区分待启用、等待回执、已启用、连接未建立；配置中的S3地址应与现场实际局域网一致，不能套用旧IP。`debug_hold`是调试超时保持策略，不是禁止动作开关。离线修改没有验证真实机械动作。

## 故障处理和验收

无线连接断开超过两秒会清除有效展示结果。电脑退出后显示断连；重新连接建立新会话，不补发旧命令，不恢复设备使能。损坏 JPEG 丢弃并等待下一帧；旧模式帧按会话和版本拒收。相机失效不阻塞原采集显示生命周期。

正式录像前记录：USB 适配器/接口、实际无线地址、两分钟帧计数、左右注入各十次、命令确认 P95、两次不同物体拍摄标识。低分辨率下要求实际动态显示至少 10 次/秒，控制 P95≤500 ms；深度推理和眼控停留另计。最后拔网线组合运行十分钟，检查原停止、断线、恢复、疲劳/情绪窗口连续性和两遍彩排。

工程内离线复查：

```powershell
python -m unittest discover -s tests -q
build/reconstruction-venv/Scripts/python.exe verify_visual_demo.py --depth
```

后者使用已登记录音、历史相机帧和软件整数参考，报告明确标为 `physical_wifi=false / physical_pl=false / physical_hdmi=false`。
