# Z20 无屏静音联调操作

系统分工：Z15 保留人的采集、交互和原控制链；Z20 接收分类器输入，执行 NPU 并返回辅助结果。当前电脑使用同一客户端暂代 Z15。所有演示关闭音频播放，分析结果不调用执行设备。

本包先按候选版本交付，验收状态见 `release.json` 和工程的 `HEADLESS_IMPLEMENTATION_STATUS.md`。无线关联、实体按键、屏幕目视、实物米制标定、平板切图和真实 Z15 安装仍需现场操作。

## 启动与查看

将压缩包解到新的独立目录，保留旧目录用于回退。当前 PL、设备树和预留内存必须与领航者 CLG400 目标匹配。启动器只运行应用，不加载 FPGA、不替换驱动或系统配置。

```
python3 manage_headless.py verify
cp config.example.json config.json
python3 manage_headless.py diagnose
python3 manage_headless.py start
python3 manage_headless.py status
```

`config.json` 的 `bind` 设为 Z20 实际维护地址。当前有线地址为 `192.168.1.20`，TCP 9020 接收特征，HTTP 9021 只读查看；9000 保留给原 S3 链。该接口供隔离实验局域网使用，尚未加入身份认证或公网访问配置。

电脑浏览器打开 `http://192.168.1.20:9021/`。`frame.png` 是板端生成并写入独立显示环的同一帧；`frame.json` 包含像素、PNG 摘要和缓冲回读结果。它可核对输出数据，屏幕的颜色、比例和窄分区还需接屏观察。

`audio.json` 单独返回同一 PCM 的波形与 FFT。完成实测标定后，`cloud.json` 返回最多 2200 个预览点，`cloud.ply` 下载最新有效点云；无有效点云时不提供旧文件。

## 电脑暂代 Z15

电脑安装自身环境的 NumPy。不要将电脑依赖清单装入板端。进入解包目录：

```
python -m z20_compute.feature_replay --host 192.168.1.20 --features assets/lemon_features.json --output replay.json
```

回放使用真实记录经过原预处理得到的 180 维情绪、20 维疲劳特征，随窗口发送原模型输出。情绪和疲劳首先验收教师一致性；LEMON 记录没有本项目的真人状态标签。疲劳候选使用合成特征探针拟合，录制数据中的教师结果覆盖清醒和轻度，尚未覆盖重度。

同一数据端只连接一个客户端。正式联合检查：

```
python verify_unified_board.py --host 192.168.1.20 --seconds 1800 --assets-root assets --models-root models --output integration_soak.json
```

该程序先核对 318 个声音向量的实际 PL 输出，再检查九页显示和至少 30 分钟并行运行。声音审计与板端样例共用最新窗口槽，发生覆盖时使用新窗口号重发同一向量，并另存调度记录，不改标签或测试划分。

## 按键与输入

KEY1 短按依次进入总览、情绪、疲劳、测距、点云、人狗、声音分类、音频分析、AD/DA 准备。长按 0.8 秒返回总览。KEY2 的当前动作显示在页底；总览中只冻结预览，后台采集和脑电继续运行。软件事件检查与实体按键验收分开。

人狗照片页使用相机实际像素与三张登记照片配准；视频页按源时间戳回放已复核标注。图内人狗距离使用登记参考尺寸计算，与摄像头到平板屏幕的物理距离分开。首版不提供通用行为模型。声音页切换三类登记录音样例，推理显示实际结果，不用预期标签覆盖误分类。

当前相机按硬件帧完成时间配对，最大差 5 ms。两路计数可有固定偏移，仍分别检查完整帧、写入槽、覆盖和过期；完成时间接近不等于传感器同步曝光。首轮标定和测距使用静止棋盘、静物。

## 返场标定

保持相机安装和镜头不动，准备打印棋盘并实测格长。停止服务，在 `config.json` 中将 `record_pairs` 设为独立采集目录，再启动；服务从同一个采集所有者保存最多 20 组 PGM 图像，间隔至少 2 秒。移动棋盘至不同位置和角度，每次停稳后采集。不要同时另起相机进程。

将采集目录复制到电脑，用实际内角点列数、行数和实测格长运行：

```
python prepare_board_calibration.py --pairs 棋盘目录/pairs.json --columns 实际列数 --rows 实际行数 --square-m 实测格长米 --output calibration
```

该电脑步骤需要 OpenCV、SciPy 和 NumPy。检查重投影及校正垂直误差，保留原始图像、格长和报告。把生成的整个 `calibration` 目录复制到包内，停止服务，设置 `calibration` 为该目录、`record_pairs` 为 null，再启动。标定与采集模式、图像尺寸绑定，不接受以前另一种缩放模式的文件。

用至少三个实测距离检查中央 32×32 区域的中位数距离，记录真值、结果、有效点数和环境。之后检查米制点云。未标定、视差不足、结果过期时保持无效。

## Z15 恢复后接入

解开 `z15/z15_auxiliary_adapter.zip`，先读其中 README 并运行版本预检。参考副本只用于核对，不覆盖原源码或权重。在原采集程序创建情绪、疲劳实例后安装可撤销特征观察钩子；保持单一采集器。先用同一回放对照电脑结果，再恢复人的实际输入。

辅助结果供汇总展示，原眼控、媒体、停止规则、S3/STM32 和执行权限保持原链。网络断开只清空辅助结果，重连建立新会话，不补发离线旧窗口。最后回归原控制链。

USB Wi-Fi 模块为 0bda:b733。驱动必须匹配实际运行的 Linux 5.4.0-xilinx-v2020.2 和符号版本。先检查构建、正常加载/卸载和网卡识别记录，再用现场热点测试关联、收发和掉线重连。未进行关联测试时不要记录无线通过。

板载采音与 MC8008 保留接口准备。真实采样、模拟量程、接线和 DAC 输出单独验收；实验室静音期间不启动播放或模拟输出。

## 停止与恢复

```
python3 manage_headless.py stop
```

启动器保存进程身份，只停止由当前解包目录启动的进程；若身份改变则拒绝发送信号。停止后显示失效状态，释放相机、按键、显示和 NPU。错误日志为 `run/service.log`。

恢复上一应用版本：停止当前服务，回到保留的旧目录，按其原命令启动。Z15 的观察钩子按适配包 README 撤销。没有安装系统自启动，重启后按人工启动流程核对。

`recovery/headless_baseline.zip` 保存本次动工时的 SD 内核、PL、设备树、内核配置和活动 FDT；摘要见 `recovery/baseline.json`。它用于核对和人工恢复参考，不由启动器自动刷写。恢复系统前先核对板型、原 U-Boot 启动命令及 SD 路径，保留现场最新文件。当前编译中的新内核只为驱动符号表服务，不替换运行内核。
