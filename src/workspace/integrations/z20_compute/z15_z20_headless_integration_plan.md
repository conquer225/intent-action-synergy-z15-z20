# Z15／Z20 联合演示准备计划

更新日期：2026-10-25。当前约束：Z15 暂时不可用，现场没有 HDMI 屏幕，实验室全程静音，USB Wi-Fi 已插入 Z20。本阶段准备可独立检查的 Z20 与 Z15 对接包，恢复 Z15 后做真实双板和显示验收。

## 已批准实施的最新约定

本节覆盖下方早期草案中不同的输入与验收约定。实际进度与证据见 [实施记录](HEADLESS_IMPLEMENTATION_STATUS.md)。

- 首版 Z15／电脑保留原脑电预处理，发送原分类器实际使用的情绪 180 维、疲劳 20 维特征。旧原始脑电入口保留兼容检查，不作为当前板端启动依赖。
- 先复现 SEED 三类权重与 HGB 教师分档，检查教师一致性；疲劳阈值保留 0.35／0.70。真实标签不足时，合成特征探针单列为诊断/教师拟合材料，不记作录制脑电或真人准确率。
- 当前没有热点，不安排临时热点验收。先通过有线维护网络完成电脑→Z20→电脑真实往返，驱动先验编译、加载、卸载及无线接口出现。无线关联留返场。
- 数据 TCP 使用 9020，无屏 HTTP 使用 9021。共用同一客户端，避开 S3 9000；按本机接收时限、会话和序号管理新鲜度。大画面/文件与分类小消息分别传输。
- NPU 串行访问；相机由单一所有者取得快照；切换前台不重置原脑电窗口、校准或原 Z15 状态。未知、断线、过期时清空有效结果。
- ARM 运行模块兼容 Python 3.7、NumPy 1.17。板端默认路径不依赖 SciPy，不导入已知崩溃的 Python cv2；沿用已验证原生图像库。
- KEY1 短按循环总览、情绪、疲劳、测距、点云、人狗、声音、音频分析、AD/DA 准备页；长按 0.8 秒回总览。KEY2 切换页内详情/样例/角度。消抖 50 ms，按住不重复，上电按住先等释放。软件事件与实体按键分开验收。
- 首版人狗保留登记素材像素配准、时间戳标注回放及参考尺寸估算。未实物标定的双目/点云不发布有效米制结果；保留标定、校正、视差、单帧点云及电脑查看入口。
- 文件声音三分类按源录音分组训练/测试，同时计算波形、音量和 FFT，全程不播放。真实板载采音、MC8008 量程及输出留独立现场验收。
- 连续运行至少 30 分钟，检查进程、内存、有界队列、错误与新鲜度。发布包独立解包并核对模型/素材摘要，保留启动、停止、诊断和恢复入口。
- 交付 Z20 包、电脑模拟端、无屏页面、Z15 适配副本、联调手册/证据五部分。真实 Z15 安装、无线链路、HDMI、实体按键、棋盘测距和平板切换不记作当前通过。冷启动/网络恢复/静音检查通过后再启用正式自启动。

## 目标与分工

Z15 负责人自身信息的采集管理、交互和原执行控制链。Z20 负责辅助运算以及外部视觉、声音情况的分析，再把结果送回 Z15。人的状态分析、外部环境信息与控制请求分别保留含义。首版辅助结果用于提示和展示，不自动触发灵巧手或倒立摆；S3/STM32 原执行链和启停规则保留。

用户已同意首版允许真实录制脑电和声音回放，人狗使用固定素材，双目测距使用真实静物。三个人脸身份分类暂缓。板载麦克风、MC8008 真实采样输出与现场佩戴泛化另列硬件和模型验收，不把文件回放记为这些功能通过。

当前信息流：电脑模拟 Z15 的采集发布端 → 与正式客户端相同的协议 → Z20 实际计算和感知 → 电脑模拟 Z15 的结果接收端。接回 Z15 时替换数据源和汇总入口，复用协议、结果结构和计算程序。模拟对接不能替代 Z15 实际系统的依赖、安装和共存检查。

## 当前已核对的起点

领航者 ATK-DF7010/7020P、XC7Z020 CLG400，当前 Linux 为 5.4.0-xilinx-v2020.2。双目／NPU 固件、人狗视频与照片程序已有实板记录；当前照片进程仍存在。独立叠加显示环已核对，HDMI 线端显示仍未验收。

本次只读检查中，USB 设备 `0bda:b733` 已出现，网络接口仍只有 eth0、lo、can0、sit0，没有无线网卡。需要核对接口绑定、驱动、固件及当前内核构建条件；不能将 USB 枚举成功写成 Wi-Fi 已可联网。

## 阶段一：保护基线与静音运行

保存实际内核、设备树、PL、运行目录、接口和包摘要，建立此次检查记录。保留已有可用双目固件与恢复入口。多项任务共用板卡时，一次只有一个板端部署所有者。

不播放音频样例，不执行测试音，不加载旧音频镜像。声音分类、波形、音量条和 FFT 均先读取文件并只计算。新硬件涉及蜂鸣器或音频输出时，先检查默认关闭行为；DAC 输出也默认禁用。网络接入和无屏检查不依赖发声。

验收：稳定取得相机状态、进程和结果；默认启动及异常恢复不启动音频播放；原可用固件与包有可回退记录。

## 阶段二：USB Wi-Fi

读取实际 USB 接口描述、绑定信息和内核能力，找到匹配源码与固件。按当前 ARM 架构、内核版本、配置和符号版本构建适配，先在现有系统中验证，不以替换整套启动镜像作为默认步骤。

当前用电脑／手机测试热点或可互访的现有局域网替代不可用的 Z15 热点。网络名称和凭据写入本机私有配置，不写入发布包或日志。恢复 Z15 后，将同一连接入口切到 Z15 现有局域网；不改动原 S3 网络。

先验证网卡出现、获取地址、双向连接，再测试持续小数据传输、断线重连和有线维护路径。记录实测吞吐和延迟，不用模块标称速率作结果。

验收：Z20 经无线网卡真实收发数据；USB 或热点断开时程序清空过期结果，连接恢复后建立新会话；保留串口和有线恢复方式。

## 阶段三：电脑模拟 Z15，对接正式接口

电脑使用可部署到 Z15 的同一客户端模块，发送八通道、250 Hz、微伏单位的脑电记录，接收 Z20 的结果。保留输入来源、通道表、样本序号、会话和质量；Z20 返回任务、模型版本、窗口／帧编号、有效状态和失效原因。

先沿用已有有界 TCP 协议和服务入口，扩展所需的外部感知与模式结果；不占用 S3 TCP 9000。控制消息、脑电与预览／文件分开排队，大数据不阻塞状态和心跳。两板单调时钟不能直接相减；先按会话、序号及接收时限管理新鲜度，实际跨机延迟另行测量。

测试暂停发送、序号缺口、重新连接、旧会话结果、模式切换和故意慢分析。断流要清空旧结论，重连不补发已过期的动作或分析结果。模拟器不连接执行设备。

验收：同一段数据经电脑 → 无线 Z20 → 电脑完成真实往返，日志能追溯每份输入与结果；有效性与过期行为符合协议测试。

## 阶段四：情绪与疲劳 NPU 辅助计算

先核对可用数据、标签、通道和原模型。情绪目标为负向／中性／正向；疲劳三档需要记录划分依据。已有 LEMON 静息记录可验数据通路与处理过程，但缺少本工程目标真值，不用作情绪／疲劳准确率标签。

使用合法可用的带标签数据训练小型整数网络，按被试或录制组划分训练和评估，避免同一记录窗口泄漏。原 Z15 的 HGB、SVM 等保留对照，不直接当成已有 NPU 权重。材料不齐时明确记录缺项，不用合成标签或播放顺序代替模型输出。

实板运行真实 NPU 权重，检查同输入下 PS 与 PL 数值，记录实际后端和耗时。脑电后台持续处理，切换前台详情不重置滤波、校准和窗口。当前验收使用回放，现场佩戴的泛化和准确率另验。

验收：两项各有模型、预处理版本、来源、测试记录与板端结果；电脑发送的样本能关联到 NPU 输出，并在模拟 Z15 汇总页显示。

## 阶段五：外部视觉与声音

人狗复用已部署的视频和照片接口。视频标注回放、照片像素配准和通用检测模型分别记录；保持未知／过期清空。真实平板切图须有实际相机输入，固定素材文件测试不能替代它。

双目测距先用纸盒或书本等静物。打印已有棋盘并量实际格长，采集当前裁剪模式下不同姿态的左右图，计算标定并用独立已知距离验证。输出距离、有效率、误差和处理时间；标定未完成时不输出未经验证的真实米数。

点云先做一个静物、一个视角的实际深度点集和电脑可查看文件，再扩展多视角拼接。保留电脑辅助选项，不承诺板端实时房间建图。

声音先以拍手、口哨、敲击文件作为输入，提取特征、训练并实际运行三分类。界面显示来源、波形、音量与 FFT，保持音频播放关闭。文件模型与板载麦克风、MC8008 采样输入之间的一致性待硬件接入后验证。

验收：视觉／声音结果使用统一元数据回传到模拟 Z15；数据来源和距离性质可辨认；静物标定、平板实拍的缺失条件单独列出。

## 阶段六：按键与无屏展示

采用“联机总览、人的状态辅助、视觉环境、声音环境”的统一信息组织。功能页内保留原八项任务的覆盖关系，不临时增加人脸身份。Z20 按键选择详情和任务；脑电辅助任务继续后台运行。拟用 KEY1 短按下一页、KEY2 执行当前页操作、KEY1 长按返回总览，实际按下、消抖和长按须验证。

没有 HDMI 时，由电脑浏览器查看 Z20 生成的同一份画面和结构化结果，并显示当前模式、按键事件、输入来源、处理后端和有效状态。保存截图与缓冲摘要。若实体按键无人可按，先完成注入式测试并明确保留实物按键验收，不能把程序模拟事件当成实际按下。

验收：按键和远程请求进入同一模式管理入口；切换任务不保留旧结果、不重置后台脑电；电脑能查看实际板端结果。HDMI 线端比例、颜色、窄条在恢复屏幕后另验。

## 阶段七：接回 Z15 的交付包

交付内容包括 Z20 运行包、USB Wi-Fi 驱动与构建来源、模型与素材清单、配置模板、电脑模拟 Z15 程序、Z15 客户端适配包、汇总结果页适配、启动／停止／诊断入口，以及检查记录和回退步骤。

Z15 适配包以当前 GuardianLoop_Submission_20261025 基线准备，在副本中做安装预检和模拟测试，不修改不可用 Z15 的真实环境。保留当前原模型、S3 会话、眼控、媒体与执行端。安装前必须核对恢复后的板端版本，不能仅按旧路径覆盖。

先形成一个前台启动入口，稳定后准备受控启动配置。冷启动、网络重连和停止行为通过后再启用自启动，仍遵守全程静音。正式结果不依赖临时手工修改或只有一个未归档的 /tmp 目录。

## 用户返回后的现场联调

1. 恢复 Z15，核对当前版本和原功能，用原停止流程保持执行设备停用。
2. 将 Z20 接入 Z15 现有局域网，确认服务与地址，不改 S3 的原连接。
3. 先由 Z15 发同一段脑电回放，核对与电脑模拟器一致的 Z20 结果返回。
4. 接入原采集器的数据副本，检查通道、单位、质量和窗口；原模型与新模型分开显示。
5. 实按 Z20 按键，查看 Z15 汇总与 Z20 详情一致；接屏后确认颜色、比例和窄分区。
6. 放置已知距离的静物，切换平板照片，检查视觉结果及无效清空。
7. 在用户允许的条件下，分别验收麦克风、MC8008 及后续真实输入；声音播放保持另行显式开启。
8. 最后复测原眼控和执行链，以及断连、停止和重启恢复。

## 当前需要的条件与完成口径

现在仍需一个可供 Z20 与电脑互访的测试 Wi-Fi；Z15 热点恢复前可用临时测试网络。带标签脑电材料需核对可用性；米制双目标定需要实物棋盘姿态采集和尺量；真实平板切图及按键需要现场操作。屏幕恢复后才能签收 HDMI 输出。

本阶段完成应表示：Z20 运行包、真实无线通信、电脑模拟 Z15 的往返、可用模型与结果页面、素材和对接包已在相应环境验证；未完成的现场项有明确清单。它不表示真实 Z15、实体 HDMI 或尚无输入的硬件已经通过。目标是让用户返回后集中做接入与现场验收，减少重新配置和排查基础链路的工作。
